# 11. User and Group Management

Linux Basics topic 06 introduced users and sudo. This topic looks at what happens behind the scenes.

## Everyday Commands

```bash
useradd sara            # create a user
id sara                 # UID, GID and groups
passwd sara             # set the password
compgen -u              # list every user name
userdel sara            # remove the user (keeps /home/sara)
userdel -r sara         # remove the user and the home directory
```

## Behind the Scenes of useradd

`useradd` reads its defaults from two files:

| File | Provides |
|---|---|
| `/etc/login.defs` | UID and GID ranges, password ageing defaults, `UMASK`, `CREATE_HOME yes`, mail directory (`/var/spool/mail`) |
| `/etc/default/useradd` | Default shell, home base directory (`/home`), skeleton directory (`/etc/skel`) |

It then writes to the four files of the **local user database**, which are checked at every login:

| File | Holds | Safe editor |
|---|---|---|
| `/etc/passwd` | Accounts | `vipw` |
| `/etc/shadow` | Password hashes and ageing | `vipw -s` |
| `/etc/group` | Groups | `vigr` |
| `/etc/gshadow` | Group passwords and admins | `vigr -s` |

Finally it creates `/home/sara` and copies the default dotfiles (`.bashrc`, `.bash_profile`) from **`/etc/skel/`**. Put files in `/etc/skel` and every new user gets them.

## /etc/passwd: 7 Fields

```text
sara:x:1001:1001:Sara Khan:/home/sara:/bin/bash
 1   2  3    4      5          6          7
```

| # | Field |
|---|---|
| 1 | User name |
| 2 | Password: `x` means it is stored in `/etc/shadow` |
| 3 | UID (user ID) |
| 4 | GID (primary group ID) |
| 5 | GECOS: a comment, usually the full name |
| 6 | Home directory |
| 7 | Login shell |

## /etc/shadow: 9 Fields

```text
sara:$6$xyz...:19800:0:90:7:14:20200:
 1      2        3   4  5 6  7    8   9
```

| # | Field |
|---|---|
| 1 | User name |
| 2 | Password **hash**. RHEL uses SHA-512 (`$6$`) or yescrypt (`$y$`). `!` or `*` means locked |
| 3 | Date of the last password change (days since 1 January 1970) |
| 4 | Minimum days before the password may be changed again (0 = any time) |
| 5 | Maximum days before it must be changed |
| 6 | Days of warning before it expires |
| 7 | Inactive days: grace period after expiry before the account is disabled |
| 8 | Account expiry date (days since 1970) |
| 9 | Reserved |

Read the details with `man 5 shadow`, and manage ageing with `chage`:

```bash
chage -l sara           # show the ageing settings
chage -M 90 -W 7 sara   # must change every 90 days, warn 7 days before
chage -d 0 sara         # force a password change at the next login
chage -E 2026-12-31 sara   # account expires on that date
```

## Groups

```bash
groupadd developers
getent group developers          # one group's entry
usermod -aG developers sara      # ADD a secondary group (keep the others)
usermod -g developers sara       # change the PRIMARY group
gpasswd -d sara developers       # remove sara from the group
groups sara
```

- A user has one **primary** group (field 4 of `/etc/passwd`) and any number of **secondary** groups.
- New files a user creates belong to their **primary** group. Secondary groups give access to other groups' files.

> ⚠️ `usermod -G developers sara` without `-a` **replaces** all of sara's secondary groups, which can silently remove her from `wheel` (sudo).

## Modifying Users

```bash
usermod -u 5000 -d /opt/sara -m -c "Test user" -s /bin/sh sara
useradd -u 5000 -d /opt/sara -c "Test user" -s /bin/sh sara    # the same options at creation
```

| Option | Sets |
|---|---|
| `-u` | UID |
| `-d` | Home directory (`-m` with usermod also moves its contents) |
| `-c` | Comment |
| `-s` | Login shell |
| `-l` | New login name (usermod) |

## Disabling an Account

| Method | Effect |
|---|---|
| `passwd -l sara` / `usermod -L sara` | Locks the password (adds `!` to the hash); `passwd -u` / `usermod -U` unlocks |
| `usermod -s /sbin/nologin sara` | The account can't get a shell (good for service and FTP-only accounts) |
| `chage -E 0 sara` | Expires the account immediately |
| `touch /etc/nologin` | Blocks **all** non-root logins (maintenance); delete the file to allow them again |

> ⚠️ Never empty the password field in `/etc/passwd` or `/etc/shadow` to "disable" a user: an empty field can mean **no password is needed**. Commenting a user out of `/etc/passwd` makes `su - sara` fail with "user does not exist", but editing these files by hand is risky; use the commands above.

## Aliases

An **alias** is a nickname for a command.

```bash
alias ll='ls -l'               # no spaces around =
alias rm='rm -i'               # always ask before deleting
alias                          # list all aliases
unalias ll
```

Aliases typed in the shell disappear when you log out. Make them permanent in `~/.bashrc` (one user) or `/etc/bashrc` (everyone), then run `source ~/.bashrc`.

## Questions

1. Create `deploy` as a service account that can't log in, with home `/opt/deploy`.
2. Force `sara` to choose a new password at her next login.
3. Which file controls the default UID range for new users?

<details>
<summary>Answers</summary>

1. `useradd -d /opt/deploy -s /sbin/nologin deploy`
2. `chage -d 0 sara`
3. `/etc/login.defs` (`UID_MIN` and `UID_MAX`).
</details>
