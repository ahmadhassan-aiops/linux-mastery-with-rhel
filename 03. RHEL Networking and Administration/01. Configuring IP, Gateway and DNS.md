# 01. Configuring IP, Gateway and DNS

To reach the internet, a Linux server needs three settings:

| Setting | Purpose | Example |
|---|---|---|
| **IP address + netmask** | The server's own address on the network | `192.168.1.50/24` (netmask `255.255.255.0`) |
| **Default gateway** | The router that forwards traffic to other networks | `192.168.1.1` |
| **DNS server** | Translates names like `google.com` into IP addresses | `8.8.8.8` |

The IP needs a **network card** (NIC), which needs a **driver** loaded by the kernel.

## Networking Basics

- **Same network, no router needed.** Servers whose addresses are in the same network (for example `192.168.1.1` to `192.168.1.254` with a `/24` mask) talk directly through a **switch**.
- **Different networks need a router.** `192.168.0.10` and `192.168.1.10` are on different `/24` networks, so traffic must cross a **router**, which joins networks and lets packets "jump" from one to another.
- **The gateway** is the router's address on *your* side. Each server must know it, or it can't send anything beyond its own network.
- **Intranet.** If the internet link goes down, servers on the same switch still talk to each other (for example, to copy files). They just can't reach the outside world.
- You may have several gateways for different routes, but only **one default gateway**.

## Inspect the Current Settings

```bash
ip a                    # interfaces and addresses (ip addr list does the same)
ip r                    # routing table (ip route list); "default via ..." is the gateway
cat /etc/resolv.conf    # DNS servers ("nameserver 8.8.8.8")
nmcli device status     # NetworkManager's view of every interface
lspci | grep -i ethernet   # the physical network card
ethtool enp0s3          # speed, duplex and link status of a card
ping -c 4 google.com    # replies keep coming = connected
```

`ifconfig` and `route -n` are the older tools from the `net-tools` package; `ip` replaces both.

## RHEL 8 and 9: NetworkManager

On RHEL 8 and 9, **NetworkManager** owns the network configuration. Use either the text menu `nmtui` or the command `nmcli`.

### With nmtui

```bash
nmtui
```

Choose **Edit a connection**, select the interface, set **IPv4 configuration** to **Manual**, enter the address with its prefix (`192.168.1.50/24`), the gateway and the DNS server, then **OK**. Choose **Activate a connection** to deactivate and reactivate it.

### With nmcli

```bash
nmcli connection show                       # find the connection name, e.g. enp0s3

nmcli connection modify enp0s3 \
  ipv4.addresses 192.168.1.50/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns "8.8.8.8 1.1.1.1" \
  ipv4.method manual \
  connection.autoconnect yes

nmcli connection down enp0s3 && nmcli connection up enp0s3
ip a show enp0s3
ip route show
```

To go back to DHCP: `nmcli connection modify enp0s3 ipv4.method auto`.

Settings are stored in `/etc/NetworkManager/system-connections/<name>.nmconnection`. If you edit that file by hand, run `nmcli connection reload` and bring the connection up again.

## RHEL 6: The Old Way

```bash
setup                                   # text menu: Network configuration > Device configuration
vi /etc/sysconfig/network-scripts/ifcfg-eth0
service network restart                 # all interfaces
ifdown eth0 && ifup eth0                # one interface
```

A typical `ifcfg-eth0` file:

```text
DEVICE=eth0
ONBOOT=yes
BOOTPROTO=static        # or dhcp
IPADDR=192.168.1.50
NETMASK=255.255.255.0
GATEWAY=192.168.1.1
DNS1=8.8.8.8
```

RHEL 6 also ran NetworkManager alongside the classic `network` service; admins often disabled it on servers with `service NetworkManager stop` and `chkconfig NetworkManager off`.

### Temporary Changes (Lost at Reboot)

```bash
ip addr add 192.168.1.60/24 dev enp0s3        # add an address now
ip route add default via 192.168.1.1          # set the default gateway now
ifconfig eth1 192.168.0.103 netmask 255.255.255.0   # old syntax
route add default gw 192.168.1.1                    # old syntax
```

These live only in memory. Use `nmcli` (or the ifcfg file on RHEL 6) for permanent settings.

## DNS: Names to IP Addresses

DNS (Domain Name System), also called the **name server**, does **name to IP resolution**. Nobody can remember the IP address of every website, but names like `google.com` are easy.

When you open `facebook.com`:

1. The system checks `/etc/hosts` for a local entry.
2. It asks the DNS server listed in `/etc/resolv.conf` (for example `nameserver 8.8.8.8`).
3. The DNS server returns Facebook's public IP.
4. The browser connects to that IP.

Well-known public DNS servers:

| Address | Provider |
|---|---|
| `8.8.8.8`, `8.8.4.4` | Google Public DNS |
| `1.1.1.1`, `1.0.0.1` | Cloudflare |
| `9.9.9.9` | Quad9 |
| `4.2.2.2` | Level 3 (Lumen) |

> 💡 `8.8.8.8` is Google's **DNS server**, not the address of google.com.

RHEL Services topic 07 explains DNS in depth and builds a DNS server.

## Troubleshooting Checklist

| Symptom | Check |
|---|---|
| No IP address | `nmcli device status`; is the connection set to connect automatically (`ONBOOT=yes` on RHEL 6)? Is the method `auto` (DHCP) or a correct static address? |
| `ping 192.168.1.1` fails | Cable or virtual network adapter, netmask, the interface is up (`ip link`) |
| `ping 8.8.8.8` fails | Default gateway (`ip r`) |
| `ping 8.8.8.8` works, `ping google.com` fails | DNS: `cat /etc/resolv.conf`, add `ipv4.dns 8.8.8.8` with nmcli |

## Questions

1. A new server can ping `8.8.8.8` but not `google.com`. What is wrong, and how do you fix it on RHEL 9?
2. Two servers, `10.0.0.5/24` and `10.0.1.5/24`, can't talk to each other through the same switch. Why?
3. Give `enp0s3` the static address `10.10.10.20/24`, gateway `10.10.10.1`, DNS `1.1.1.1`.

<details>
<summary>Answers</summary>

1. DNS isn't configured: `nmcli connection modify enp0s3 ipv4.dns 8.8.8.8 && nmcli connection up enp0s3`.
2. They are on different networks (`10.0.0.0/24` and `10.0.1.0/24`), so traffic needs a router.
3. `nmcli connection modify enp0s3 ipv4.addresses 10.10.10.20/24 ipv4.gateway 10.10.10.1 ipv4.dns 1.1.1.1 ipv4.method manual && nmcli connection up enp0s3`
</details>
