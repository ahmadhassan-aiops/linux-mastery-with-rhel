# 07. Installing from Source Code

**Source code installation** (a "tarball installation") compiles a program yourself. Packages from `dnf` are built with the distribution's default options; compiling lets you choose the features, the version and the install location.

## The Three Commands

```bash
./configure      # check dependencies and generate the Makefile
make             # compile
make install     # copy the result into place
```

## Example: Apache httpd

```bash
# 1. Build tools and libraries
dnf install gcc make redhat-rpm-config apr-devel apr-util-devel pcre2-devel openssl-devel

# 2. Download and unpack
wget https://downloads.apache.org/httpd/httpd-2.4.62.tar.bz2
tar jxvf httpd-2.4.62.tar.bz2
cd httpd-2.4.62
less INSTALL             # the project's own instructions

# 3. Configure with your own options
./configure --prefix=/usr/local/apache2 --enable-ssl --enable-so --disable-proxy
echo $?                  # 0 means the previous command succeeded

# 4. Compile and install
make
make install

# 5. Run it
/usr/local/apache2/bin/apachectl start
```

> 💡 The version number above is an example. Check https://httpd.apache.org/download.cgi for the current release and its exact file name.

- `./configure` checks that compilers and libraries are present and writes the **Makefile**, the recipe `make` follows.
- `./configure --help` lists every option.
- `make` compiles the modules with `gcc`.
- `make install` copies the files into the `--prefix` directory, the job `rpm -ivh` does for packages.

## RPM vs Source

| | RPM / DNF | Source |
|---|---|---|
| Files go to | Standard places (`/usr/bin`, `/etc`, `/var`) | One folder, usually under `/usr/local` |
| Updates | `dnf update` | Recompile by hand |
| Uninstall | `dnf remove` | `make uninstall` if the project supports it, or delete the prefix folder (`rm -rf /usr/local/apache2`) |
| Tracked by RPM | Yes | No |
| Customization | Defaults only | Any option |

**Drawback:** source installs are harder to maintain. Security fixes don't arrive through `dnf update`, so you must track releases yourself.

## Questions

1. `./configure` stops with "APR not found". What do you install?
2. How do you tell whether `make` succeeded before running `make install`?

<details>
<summary>Answers</summary>

1. The development packages: `dnf install apr-devel apr-util-devel`.
2. Check its last lines for errors, or run `echo $?` right after it (0 means success).
</details>
