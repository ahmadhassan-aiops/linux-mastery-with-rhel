# 12. Special Permissions, sudo, PATH and umask

## SUID, SGID and the Sticky Bit

Beyond `rwx`, there are three special permissions.

| Permission | Octal | Set with | On a file | On a directory |
|---|---|---|---|---|
| **SUID** | 4 | `chmod u+s` | Runs with the **owner's** privileges (usually root) | No effect |
| **SGID** | 2 | `chmod g+s` | Runs with the group's privileges | New files inherit the **directory's group**: ideal for shared team folders |
| **Sticky bit** | 1 | `chmod o+t` | No effect | Users can delete **only their own** files, even if everyone can write there (`/tmp`) |

They appear in place of the `x`:

| Shows | Means |
|---|---|
| `s` in the user field | SUID **with** execute |
| `S` in the user field | SUID **without** execute (usually a mistake) |
| `s` / `S` in the group field | SGID with / without execute |
| `t` / `T` in the others field | Sticky bit with / without execute |

```bash
chmod u+s,g+s,o+t file
chmod 4755 /usr/local/bin/tool     # SUID + rwxr-xr-x
chmod 2775 /shared/team            # SGID directory for a team
chmod 1777 /scratch                # sticky, world-writable (like /tmp)
ls -ld /tmp                        # drwxrwxrwt
```

The first of the four octal digits is the special one: `4` SUID, `2` SGID, `1` sticky, added together (`7777` sets all of them).

### Why SUID Exists: passwd

`/etc/shadow` has **no permissions at all** (`----------`), yet every user can change their own password. That's because `/usr/bin/passwd` is SUID root (`-rwsr-xr-x`): while it runs, it has root's rights to update the shadow file. Remove SUID from `passwd` and normal users can no longer change their passwords.

### Finding Special-Permission Files

```bash
find / -perm -4000 -type f 2>/dev/null    # SUID
find / -perm -2000 -type f 2>/dev/null    # SGID
find / -perm -1000 -type d 2>/dev/null    # sticky bit
find / -perm /7000 2>/dev/null            # any of the three
```

Audit SUID files regularly: an unexpected SUID root program is a classic privilege-escalation hole.

> ⚠️ `chmod u+s /sbin/fdisk` would let **every** user run fdisk as root, and wipe disks. Use sudo to grant root commands to specific people instead.

## SUID vs sudo

| | SUID | sudo |
|---|---|---|
| Who gets the privilege | **Every** user who can run the file | **Only** the users listed in sudoers |
| Granularity | The whole program | Specific commands, even with specific arguments |
| Logged | No | Yes, in `/var/log/secure` |

## sudoers

Always edit with **`visudo`**, which refuses to save a file with syntax errors (a broken sudoers file can lock everyone out of sudo). Better still, put rules in their own file: `visudo -f /etc/sudoers.d/webteam`.

```text
# user    hosts=(run as)   commands
ahmad     ALL=/usr/sbin/fdisk -l
```

`ahmad` can now run `sudo fdisk -l`, after typing his own password.

### Without a Password

```text
ahmad ALL=(ALL) NOPASSWD: /usr/bin/systemctl start httpd
ahmad ALL=(ALL) NOPASSWD: /usr/bin/systemctl start httpd, /usr/bin/systemctl restart httpd, /usr/bin/systemctl stop httpd
```

### Command Aliases for Many Commands

Listing hundreds of commands per user doesn't scale. Group them in a **Cmnd_Alias** (the name must be in CAPITALS); sudoers already has commented examples such as `NETWORKING` and `SOFTWARE`:

```text
Cmnd_Alias WEBCTL = /usr/bin/systemctl start httpd, /usr/bin/systemctl stop httpd, /usr/bin/systemctl restart httpd
ahmad ALL=(ALL) NOPASSWD: WEBCTL
%webteam ALL=(ALL) WEBCTL          # % means a group
```

### Full Admin Rights

```bash
usermod -aG wheel ahmad            # RHEL: wheel members may run anything with sudo
```

### Root Is UID 0

The kernel doesn't care about the name "root": it grants full privileges to **UID 0**. Any account with UID 0 is a superuser. That is exactly why you must never give another account UID 0 (with `usermod -o -u 0`, or by editing `/etc/passwd`): it creates a hidden root account that bypasses sudo logging. Use the wheel group instead. Checking for extra UID-0 accounts is a standard security audit:

```bash
awk -F: '$3 == 0 {print $1}' /etc/passwd    # should print only "root"
```

## PATH

`PATH` is the list of directories the shell searches when you type a command name.

```bash
echo $PATH        # e.g. /usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin
which useradd     # where a command lives
type ll           # alias, built-in or file?
```

A program outside these directories only runs with its full path: `/opt/tools/mytool`.

Add a directory:

```bash
export PATH=$PATH:/opt/tools        # this session only
```

Make it permanent in `~/.bashrc` (one user) or a new file in `/etc/profile.d/` (everyone):

```bash
echo 'export PATH=$PATH:/opt/tools' > /etc/profile.d/tools.sh
```

> 🔐 Never add `.` (the current directory) to root's PATH: a malicious script named `ls` in some folder would then run as root.

## umask

The **umask** decides the default permissions of new files and directories. It *removes* permissions from the maximum: `666` for files, `777` for directories.

| umask | New file | New directory |
|---|---|---|
| `022` | 666 - 022 = **644** `rw-r--r--` | 777 - 022 = **755** `rwxr-xr-x` |
| `027` | **640** `rw-r-----` | **750** `rwxr-x---` |
| `077` | **600** `rw-------` | **700** `rwx------` |

Output (captured on a Linux machine):

```text
$ umask
0022
$ touch newfile && mkdir newdir && ls -ld newfile newdir
drwxr-xr-x 2 root root 4096 Oct 21 19:10 newdir
-rw-r--r-- 1 root root    0 Oct 21 19:10 newfile
$ umask 027; touch f2; mkdir d2; ls -ld f2 d2
drwxr-x--- 2 root root 4096 Oct 21 19:10 d2
-rw-r----- 1 root root    0 Oct 21 19:10 f2
```

Files never get execute by default: you add it with `chmod +x`.

`umask 027` in a shell lasts until logout. Set it permanently in `~/.bashrc`, `/etc/bashrc` or the `UMASK` line of `/etc/login.defs`.

## Questions

1. Members of `devops` share `/srv/project`. New files must belong to the `devops` group automatically, and users mustn't delete each other's files. Which permissions?
2. Let `sara` restart `httpd` with sudo, without a password, and nothing else.
3. With umask `007`, what permissions does a new file get?

<details>
<summary>Answers</summary>

1. `chgrp devops /srv/project && chmod 3770 /srv/project` (SGID + sticky + rwxrwx---).
2. With `visudo -f /etc/sudoers.d/sara`: `sara ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart httpd`
3. `660` (`rw-rw----`).
</details>
