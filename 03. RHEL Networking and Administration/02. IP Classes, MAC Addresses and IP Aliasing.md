# 02. IP Classes, MAC Addresses and IP Aliasing

## IPv4 and IPv6

| | IPv4 | IPv6 |
|---|---|---|
| Size | 32 bits, written as 4 octets | 128 bits, written as 8 groups of 4 hex digits |
| Example | `192.168.1.10` | `2001:db8::8a2e:370:7334` |
| Addresses | About 4.3 billion: practically used up | Practically unlimited |
| Today | Still the most common, stretched by NAT | Growing; runs alongside IPv4 |

## IP Classes

The original IPv4 scheme split addresses into classes by their first octet:

| Class | First octet | Default mask | CIDR | Private range |
|---|---|---|---|---|
| **A** | 1 to 126 | `255.0.0.0` | `/8` | `10.0.0.0/8` |
| **B** | 128 to 191 | `255.255.0.0` | `/16` | `172.16.0.0/12` (172.16 to 172.31) |
| **C** | 192 to 223 | `255.255.255.0` | `/24` | `192.168.0.0/16` |
| D | 224 to 239 | | | Multicast |
| E | 240 to 255 | | | Reserved |

`127.0.0.0/8` is **loopback** (the machine itself).

Classes are largely history: modern networks use **CIDR** (Classless Inter-Domain Routing), where the `/number` says how many bits belong to the network. `192.168.1.0/24` means the first 24 bits (`192.168.1`) are the network and the last 8 bits number the hosts (`.1` to `.254`).

**Private** addresses are free to use inside any organization but are not routed on the internet; routers translate them to public addresses with **NAT**.

## MAC Addresses

Every network card has a **MAC address** (Media Access Control), such as `08:00:27:3a:1b:9c`.

- It is burned into the card and meant to be unique worldwide. The OS can override it in software, but the hardware value stays the same.
- `ip link` shows it (`link/ether ...`).

| | IP address | MAC address |
|---|---|---|
| Layer | 3 (Network) | 2 (Data Link) |
| Purpose | **Where** a system is: routing across networks | **Delivery** to the right card on the local network |
| Changes when | You move to another network | Practically never |

Every machine also has the **loopback interface** `lo` (`127.0.0.1`), present even without any network card. Programs use it to talk to services on the same machine.

## IP Aliasing

**IP aliasing** gives one network card several IP addresses. The card's driver handles all of them.

**Why?** A server can join a second network without another card or a router, or host several services that each need their own address.

### Temporary (Lost at Reboot)

```bash
ip addr add 10.0.2.16/24 dev enp0s3          # modern
ifconfig enp0s3:1 10.0.2.16 netmask 255.255.255.0   # old alias syntax (RHEL 6)
ip a show enp0s3                             # both addresses are listed
```

### Permanent (RHEL 8 and 9)

```bash
nmcli connection modify enp0s3 +ipv4.addresses 10.0.2.16/24
nmcli connection up enp0s3
```

The `+` adds the address to the existing ones instead of replacing them. Remove it with `-ipv4.addresses 10.0.2.16/24`.

On RHEL 6, the permanent way was a file `/etc/sysconfig/network-scripts/ifcfg-eth0:1` with its own `DEVICE=eth0:1` and `IPADDR=`.

## Questions

1. Is `172.20.5.4` a private or public address? Which class?
2. How many usable host addresses are in a `/24` network?
3. Add `192.168.50.10/24` to `enp0s3` permanently, keeping its current address.

<details>
<summary>Answers</summary>

1. Private (inside `172.16.0.0/12`), class B.
2. 254 (256 minus the network and broadcast addresses).
3. `nmcli connection modify enp0s3 +ipv4.addresses 192.168.50.10/24 && nmcli connection up enp0s3`
</details>
