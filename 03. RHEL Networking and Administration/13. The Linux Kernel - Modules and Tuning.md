# 13. The Linux Kernel - Modules and Tuning

The **kernel** is the heart of the operating system. It manages the CPU (the **scheduler**), memory, devices (through **drivers**), file systems and networking, and gives programs the system calls they use.

## The Kernel on Disk

It lives in **`/boot`**:

| File | Purpose |
|---|---|
| `vmlinuz-<version>` | The kernel itself: a compressed binary, written mainly in C (with assembly) |
| `initramfs-<version>.img` | A small temporary root file system that loads the drivers needed to mount the real root at boot |
| `config-<version>` | The options the kernel was built with |
| `System.map-<version>` | The kernel's symbol table, for debugging |

```bash
uname -r                    # the running kernel version
ls -lh /boot/vmlinuz-*      # about 14 MB on RHEL 9
rpm -q kernel               # every installed kernel
```

## Kernel Modules (Drivers)

Most drivers are **loadable kernel modules** (`.ko` files, "kernel objects") that can be added to or removed from the running kernel without rebooting.

They are stored under:

```text
/lib/modules/$(uname -r)/kernel/
```

```bash
find /lib/modules/$(uname -r)/kernel -name "*.ko*" | wc -l   # how many are available (RHEL compresses them: .ko.xz)
lsmod                         # which are loaded right now
modinfo e1000                 # details about one module
modprobe e1000                # load it, with its dependencies
modprobe -r e1000             # unload it
insmod /full/path/module.ko   # load one file, without resolving dependencies
rmmod e1000                   # unload, without dependency handling
depmod -a                     # rebuild modules.dep, the dependency map
```

Prefer `modprobe` over `insmod` and `rmmod`: it handles dependencies.

### Seeing Hardware and Drivers

```bash
dmesg | less                 # kernel messages: what was detected at boot
lspci -k                     # PCI devices and the driver each one uses
lspci -vvv | grep -i audio
```

### Loading a Module at Every Boot

```bash
echo "e1000" > /etc/modules-load.d/e1000.conf
```

Module options go in `/etc/modprobe.d/<name>.conf`, for example `options e1000 debug=1` or an alias such as `alias audio snd_hda_intel`.

### Blacklisting a Module

To stop a driver from ever loading (for example, a buggy or unwanted one), don't delete its file; blacklist it:

```bash
echo "blacklist nouveau" > /etc/modprobe.d/blacklist-nouveau.conf
dracut -f                    # rebuild the initramfs so it is honoured at boot too
```

Deleting `.ko` files by hand breaks package verification and comes back with the next kernel update.

### Installing a Driver from Source

Vendors sometimes ship drivers as source code:

```bash
lspci -vvv | grep -i <device>        # identify the hardware vendor and model
dnf install kernel-devel-$(uname -r) gcc make
tar -zxvf driver.tar.gz && cd driver
./configure && make && make install  # or just make && make install, per its README
modprobe <driver-name>
```

Third-party modules must be rebuilt for every new kernel; DKMS automates that.

## Kernel Updates

```bash
dnf update kernel
```

- The new kernel is installed **next to** the old one, never over it (like a car with two engines, using one at a time).
- Switching kernels needs a **reboot**. Only the kernel space changes; your files, programs and settings stay the same.
- Choose the kernel in the GRUB menu, or set the default with `grubby --set-default /boot/vmlinuz-<version>`.

## Kernel Tuning

**Kernel tuning** means changing parameters of the **running** kernel to suit a workload: memory management, networking, file handles and more. The tunable parameters live as small files under **`/proc/sys/`**, and a change takes effect instantly.

```bash
sysctl -a                         # every tunable parameter and its value
sysctl -a | grep swappiness       # find one
cat /proc/sys/vm/swappiness       # the same value, read as a file
```

### Example 1: Too Many Open Files

A busy web server fails with "Too many open files". Raise the system-wide limit, say from 300,000 to 600,000:

```bash
cat /proc/sys/fs/file-max                  # current maximum
echo 600000 > /proc/sys/fs/file-max        # change it live (echo, not vi)
sysctl -w fs.file-max=600000               # the same with sysctl
lsof | wc -l                               # roughly how many files are open now
```

The per-process limit (`ulimit -n`, or `LimitNOFILE=` in a systemd service) often needs raising too.

### Example 2: Swappiness

`vm.swappiness` (0 to 100) sets how eagerly the kernel moves memory to swap:

| Value | Behaviour |
|---|---|
| `0` | Avoid swapping as long as possible |
| `60` | The kernel default: balanced |
| `100` | Swap aggressively |

```bash
sysctl -w vm.swappiness=10        # databases often prefer a low value
```

### Making Tuning Permanent

`echo` and `sysctl -w` change only the running kernel; the values reset at reboot. To keep them, write them to a file in **`/etc/sysctl.d/`** (or `/etc/sysctl.conf`):

```bash
cat > /etc/sysctl.d/99-custom.conf <<'EOF'
fs.file-max = 600000
vm.swappiness = 10
EOF
sysctl -p /etc/sysctl.d/99-custom.conf   # load it now (sysctl --system loads every file)
```

## Types of Kernels

| Type | Idea | Examples |
|---|---|---|
| **Monolithic** | One large kernel containing drivers, file systems and process management. Fast; Linux adds loadable modules and live tuning | Linux, traditional Unix |
| **Microkernel** | Only the essentials in the kernel; drivers and services run in user space. More stable and secure, some overhead | MINIX, QNX |
| **Hybrid** | A mix: some services in the kernel, others in user space | Windows NT, macOS (XNU) |
| **Exokernel** | Applications manage hardware almost directly | Research projects |
| **Nanokernel** | An even smaller microkernel | Specialized embedded systems |
| **Real-time** | Guarantees tasks finish within strict time limits | VxWorks, RTEMS, Linux with PREEMPT_RT |

## Questions

1. Which command shows the driver used by the network card?
2. You must stop the `usb_storage` module from loading so USB drives can't be used. How?
3. Set `net.ipv4.ip_forward` to 1 now and after every reboot.

<details>
<summary>Answers</summary>

1. `lspci -k` (look at "Kernel driver in use"), or `ethtool -i enp0s3`.
2. `echo "blacklist usb_storage" > /etc/modprobe.d/blacklist-usb.conf` (add `install usb_storage /bin/false` to block manual loading too), then `dracut -f`.
3. `sysctl -w net.ipv4.ip_forward=1` and `echo "net.ipv4.ip_forward = 1" > /etc/sysctl.d/90-forward.conf`.
</details>
