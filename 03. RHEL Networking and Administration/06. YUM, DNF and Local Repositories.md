# 06. YUM, DNF and Local Repositories

**YUM** (Yellowdog Updater, Modified) installs packages from **repositories** and resolves dependencies automatically. On RHEL 8 and 9, **DNF** replaced it; the `yum` command still works and runs `dnf`.

## Everyday Commands

```bash
dnf install httpd              # install with all dependencies
dnf reinstall httpd
dnf remove httpd
dnf search rdesktop            # search names and summaries
dnf info httpd                 # details
dnf list installed             # every installed package
dnf list available             # what the repositories offer
dnf provides /usr/bin/dig      # which package contains a file
dnf repolist                   # enabled repositories
dnf check-update               # which updates are available
dnf update httpd               # update one package
dnf update                     # update everything
dnf update --exclude=kernel*   # update everything except the kernel
dnf clean all                  # clear the cache
dnf history                    # past transactions
```

## How DNF Works

When you run `dnf install httpd`:

1. It reads every `.repo` file in **`/etc/yum.repos.d/`**. Each one gives a repository's address (`baseurl`, or a `metalink` that chooses the fastest mirror).
2. It downloads each repository's index, **`repodata/repomd.xml`**: the "inventory book" listing every package and its dependencies.
3. It works out the dependencies and shows you the plan.
4. It downloads the `.rpm` files into the cache, `/var/cache/dnf/`.
5. It installs them through the RPM library (the same work `rpm -ivh` does) and, by default, deletes the cached files afterwards.

## Extra Repositories: EPEL

Some packages (for example `htop`) aren't in the RHEL repositories. **EPEL** (Extra Packages for Enterprise Linux), maintained by the Fedora project, provides thousands more. Other third-party repositories include Remi (newer PHP) and the vendors' own repositories.

```bash
# Rocky Linux and AlmaLinux
dnf install epel-release

# RHEL 9
subscription-manager repos --enable codeready-builder-for-rhel-9-$(arch)-rpms
dnf install https://dl.fedoraproject.org/pub/epel/epel-release-latest-9.noarch.rpm

dnf install htop
dnf --enablerepo=epel install htop   # use a repository that is normally disabled
```

### Repository Priority

When two repositories offer the same package, set `priority=` in a `.repo` file (lower wins, the default is 99). DNF supports it natively; on RHEL 7 install `yum-plugin-priorities` first.

## Installing Without Internet: a Local Repository

Air-gapped servers install from a local copy of the installation ISO.

1. **Make space.** The RHEL 9 DVD is about 10 GB. Add a disk if needed (in VirtualBox from the Storage settings; on VMware it can be added to a running VM, then rescan with `echo "- - -" > /sys/class/scsi_host/host0/scan`).
2. **Prepare the disk** with one partition, then format and mount it (RHEL Fundamentals topics 07 and 08):

```bash
fdisk /dev/sdb               # one partition using all the space
partprobe -s /dev/sdb
mkfs.xfs /dev/sdb1
mkdir /data && mount /dev/sdb1 /data   # and add it to /etc/fstab
```

3. **Copy the packages** from the mounted ISO:

```bash
mount -o loop rhel-9.iso /mnt
rsync -av /mnt/AppStream/Packages/ /data/
rsync -av /mnt/BaseOS/Packages/ /data/
```

4. **Create the inventory** (`repodata/repomd.xml`):

```bash
dnf install createrepo_c
createrepo -v /data
```

5. **Point DNF at it** with `/etc/yum.repos.d/local.repo`:

```ini
[local]
name=Local repository
baseurl=file:///data
enabled=1
gpgcheck=0
priority=1
```

`gpgcheck=1` verifies each package's signature. Setting it to `0` is common for a trusted local copy, but importing the Red Hat key (`rpm --import /mnt/RPM-GPG-KEY-redhat-release`) and keeping it at `1` is safer.

6. **Use it:**

```bash
dnf clean all
dnf --disablerepo="*" --enablerepo=local install httpd
```

> 💡 The RHEL 9 ISO already contains `repodata` for its `BaseOS` and `AppStream` folders, so you can also set `baseurl=file:///mnt/BaseOS` and `file:///mnt/AppStream` directly without copying.

## Patching in Production

1. Check what's available: `dnf check-update` (or `dnf updateinfo list --security` for security fixes only).
2. Get approval from every stakeholder and schedule a maintenance window.
3. Take backups (and database dumps). In a cluster, move clients to the standby server to avoid downtime.
4. Stop the affected service, apply the update (`dnf update package`), start it again and test.
5. Tell everyone it is done.

Larger estates use central patching tools: **Red Hat Satellite**, Foreman/Katello (successor of Spacewalk), or ManageEngine.

## Kernel Updates

- `dnf update kernel` installs the new kernel **alongside** the old one; it never overwrites it.
- Only one kernel runs at a time. The new one is used after a reboot; the old one stays in the GRUB menu as a fallback.
- `uname -r` shows the running kernel; `rpm -q kernel` lists the installed ones.

## Rolling Back

If an update breaks an application, undo it:

```bash
dnf history                    # list transactions with their IDs
dnf history info 15            # what transaction 15 changed
dnf history undo 15            # reverse just that transaction
dnf history rollback 12        # return to the state after transaction 12
dnf downgrade httpd            # go back one version of a package
```

## Questions

1. `dnf install htop` says "No match for argument". What do you do?
2. Update everything on a server except the kernel and `httpd`.
3. Why do you run `createrepo` when building a local repository?

<details>
<summary>Answers</summary>

1. Enable EPEL (`dnf install epel-release` on Rocky or Alma), then install again.
2. `dnf update --exclude=kernel* --exclude=httpd*`
3. It creates `repodata/repomd.xml`, the index DNF reads to find packages and dependencies.
</details>
