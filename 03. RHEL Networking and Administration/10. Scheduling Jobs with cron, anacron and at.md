# 10. Scheduling Jobs with cron, anacron and at

| Scheduler | Runs | Use for |
|---|---|---|
| **cron** | Repeatedly, on a schedule | Nightly backups, log cleanup, reports |
| **anacron** | Jobs cron missed while the machine was off | Laptops and servers that aren't always on |
| **at** | Once, at a given time | "Restart this service at 2 a.m. tonight" |

Handy helper for cron expressions: https://crontab.guru/

## cron Is a Service

```bash
systemctl status crond
systemctl enable --now crond
```

### Services: RHEL 6 vs RHEL 7+

| Task | RHEL 6 (init, PID 1) | RHEL 7 and later (systemd, PID 1) |
|---|---|---|
| Start | `service crond start` | `systemctl start crond` (loads it into RAM) |
| Stop | `service crond stop` | `systemctl stop crond` (removes it from RAM) |
| Restart | `service crond restart` | `systemctl restart crond` |
| Status | `service crond status` | `systemctl status crond`, `systemctl is-active crond` |
| Start at boot | `chkconfig crond on` | `systemctl enable crond` |

## Scheduling a Job

1. Write the script and make it executable:

```bash
vi /opt/script1.sh
chmod +x /opt/script1.sh
```

2. Edit your crontab:

```bash
crontab -e           # your own jobs
crontab -e -u ahmad  # another user's jobs (as root)
crontab -l           # list the jobs
crontab -r           # remove all your jobs (careful)
```

3. Add one line per job: **five time fields**, then the command.

```text
┌───────── minute (0-59)
│ ┌─────── hour (0-23)
│ │ ┌───── day of month (1-31)
│ │ │ ┌─── month (1-12)
│ │ │ │ ┌─ day of week (0-7: 0 and 7 are Sunday, 1 is Monday)
│ │ │ │ │
15 2 * * * /opt/script1.sh
```

| Symbol | Meaning |
|---|---|
| `*` | Every value ("always") |
| `,` | A list: `3,5` |
| `-` | A range: `1-5` (Monday to Friday) |
| `/` | A step: `*/15` (every 15) |

| Line | Runs |
|---|---|
| `15 2 * * * /opt/script1.sh` | Every day at 02:15 |
| `* * * * * /opt/script2.sh` | Every minute |
| `3,5 5 * * * /opt/script3.sh` | At 05:03 and 05:05 every day |
| `*/15 * * * * /opt/check.sh` | Every 15 minutes |
| `0 9 * * 1-5 /opt/report.sh` | 09:00, Monday to Friday |
| `0 0 1 * * /opt/monthly.sh` | Midnight on the 1st of every month |
| `@reboot /opt/startup.sh` | Once at every boot |

> 💡 Cloud schedulers (AWS EventBridge, for example) use **six** fields, adding a year. Classic cron uses five.

cron runs jobs with a minimal environment: use **absolute paths** for commands and files, and redirect output to a log: `... /opt/backup.sh >> /var/log/backup.log 2>&1`.

## How cron Works

Every minute, `crond` checks the crontabs in **`/var/spool/cron/`** (one file per user, such as `/var/spool/cron/root`). If a job's time matches the current minute, it runs; otherwise cron sleeps until the next minute.

```bash
cat /var/spool/cron/root          # root's jobs (edit with crontab -e, not directly)
cp -a /var/spool/cron /backup/    # back up every user's crontab
tail /var/log/cron                # when each job ran
```

## Controlling Who May Use cron

| File | Effect |
|---|---|
| `/etc/cron.allow` | If it exists, **only** the users listed in it may use cron |
| `/etc/cron.deny` | If there's no `cron.allow`, everyone may use cron **except** the users listed here |

RHEL ships an empty `cron.deny`, so everyone may use cron by default. Restricting it is part of **OS hardening**.

## OS Hardening: Ten Key Duties

1. Disable unnecessary services.
2. Apply security patches and updates.
3. Implement strong authentication (keys, MFA, password policies).
4. Configure the firewall.
5. Restrict administrative privileges (sudo, no direct root login).
6. Enforce file and directory permissions.
7. Enable logging and monitoring.
8. Disable unused network protocols.
9. Encrypt data at rest and in transit.
10. Install antivirus and anti-malware tools where required.

## System Jobs

cron also runs the system's own maintenance jobs. Drop a script into one of these directories and it runs on that schedule:

```text
/etc/cron.hourly/
/etc/cron.daily/
/etc/cron.weekly/
/etc/cron.monthly/
/etc/cron.d/          # crontab-format files from packages
```

## anacron

If a daily job was due at 2 a.m. but the machine was switched off, cron simply skips it. **anacron** checks when each periodic job last ran and runs it as soon as possible. Its configuration is the file **`/etc/anacrontab`**; on RHEL it runs the daily, weekly and monthly jobs above.

## at: Run Once

```bash
dnf install at
systemctl enable --now atd
at -f /opt/script.sh 4pm          # run the script at 16:00 today
at 02:00 tomorrow                 # type commands, then Ctrl+D
atq                               # pending jobs
atrm 3                            # remove job 3
```

## Questions

1. Write a crontab line that runs `/opt/backup.sh` at 23:30 every Saturday.
2. A cron job works when you run it by hand but not from cron. What are the two most likely causes?
3. Stop the user `guest` from using cron.

<details>
<summary>Answers</summary>

1. `30 23 * * 6 /opt/backup.sh`
2. The script relies on your environment (`PATH`, relative paths), or it isn't executable. Use absolute paths, `chmod +x`, and check `/var/log/cron` and the job's own output.
3. Add `guest` to `/etc/cron.deny` (when no `/etc/cron.allow` exists).
</details>
