# 04. Network Troubleshooting Tools

| Question | Tool |
|---|---|
| Can I reach that host? | `ping` |
| Which route do packets take? | `traceroute`, `tracepath` |
| Which ports are open on a host? | `nmap` |
| Is one specific port reachable? | `nc`, `telnet` |
| What is listening on *my* machine? | `ss`, `netstat` |
| What is actually on the wire? | `tcpdump` |

## ping

```bash
ping 192.168.1.1                 # runs until Ctrl+C
ping -c 5 192.168.1.1            # stop after 5 replies
ping -c 5 -s 1024 192.168.1.1    # send 1024-byte packets instead of the default 56
```

`ping` uses **ICMP** (Internet Control Message Protocol). It has no port number because it doesn't open a connection: it sends an **echo request** (ICMP type 8) and waits for an **echo reply** (type 0). The output shows the round-trip time in milliseconds and any packet loss.

> 💡 No reply doesn't always mean the host is down: firewalls often block ICMP.

## traceroute

```bash
traceroute google.com     # dnf install traceroute
tracepath google.com      # installed by default, no root needed
```

It lists every **hop** (router) between you and the destination, with the delay at each. A hop is any device that forwards your packet; where the delays jump or the list stops is where the problem is.

## nmap: Port Scanning

```bash
dnf install nmap
nmap 127.0.0.1           # open ports on this machine (via loopback)
nmap 192.168.1.10        # open ports on another host
nmap 192.168.1.0/24      # every host in the subnet (192.168.1.0 to .255)
nmap -p 22,80,443 192.168.1.10   # only these ports
nmap -sV 192.168.1.10    # also detect service versions
```

Scanning a whole subnet shows which hosts are **up** and the open ports and services on each: the standard way to discover devices on a LAN.

> ⚠️ Only scan networks you own or have written permission to test. Unauthorized scanning can break company policy or the law.

## nc and telnet: Test One Port

```bash
nc -zv 192.168.1.10 22       # -z just test, -v verbose
```

`nc` prints **succeeded** (or `Connected`) when the port is open, and **Connection refused** or a timeout when it is not. Without `-z`, `nc` keeps the connection open so you can type into it, which is handy for testing simple text protocols.

```bash
telnet 192.168.1.10 80       # the older way; Ctrl+] then quit to exit
```

## ss and netstat: What Is Listening Here?

```bash
ss -tunlp          # the modern, faster tool
netstat -tunlp     # the same with net-tools
ss -tunlp | grep 22
netstat -an        # every connection, numeric
```

| Option | Meaning |
|---|---|
| `-t` / `-u` | TCP / UDP |
| `-n` | Numeric: show `22` and `192.168.1.5` instead of `ssh` and host names |
| `-l` | Only listening sockets |
| `-p` | The process that owns each socket (run as root) |
| `-a` | All sockets, listening and connected |

Example output (illustrative) of `netstat -an`:

```text
Proto  Local Address          Foreign Address        State
tcp    192.168.1.100:80       192.168.1.101:53112    ESTABLISHED
tcp    0.0.0.0:443            0.0.0.0:*              LISTEN
tcp    127.0.0.1:3306         0.0.0.0:*              LISTEN
udp    0.0.0.0:67             0.0.0.0:*
```

| Column | Meaning |
|---|---|
| **Proto** | TCP or UDP |
| **Local Address** | IP and port on this machine. `0.0.0.0` means every interface; `127.0.0.1` means only local programs can connect |
| **Foreign Address** | The remote side of the connection |
| **State** | `LISTEN` (waiting for connections), `ESTABLISHED` (active), `TIME_WAIT` (closing), `CLOSE_WAIT` (the remote side closed; waiting for the local program) |

Uses: check which ports are open, diagnose "connection refused", and spot unexpected connections that may be a security problem.

## tcpdump: Capture Packets

```bash
tcpdump -i enp0s3                 # everything on an interface
tcpdump -i enp0s3 port 80 -n      # only HTTP, numeric
tcpdump -i any host 192.168.1.10  # traffic to or from one host
tcpdump -vvv -c 20                # very verbose, stop after 20 packets
tcpdump -i enp0s3 -w capture.pcap # save to a file for Wireshark
```

## Questions

1. A web server is running but clients get "connection refused" on port 80. Which two commands do you run on the server?
2. How do you list every machine that is up on `10.0.5.0/24`?
3. `ss -tunlp` shows MySQL on `127.0.0.1:3306`. Why can't the app server connect to it?

<details>
<summary>Answers</summary>

1. `ss -tunlp | grep :80` (is httpd listening, and on which address?) and `firewall-cmd --list-all` (is http allowed?).
2. `nmap -sn 10.0.5.0/24` (a ping scan without port scanning).
3. It only listens on loopback. Change `bind-address` in the MySQL configuration to the server's IP (and open the firewall).
</details>
