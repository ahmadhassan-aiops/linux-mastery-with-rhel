# 04. Apache Web Server and Virtual Hosts

**Apache httpd** is one of the most used web servers. It serves web pages over HTTP (port 80) and HTTPS (port 443).

## Two Ways to Host Several Websites

| Type | How |
|---|---|
| **Name-based** | Many websites share **one IP address**; Apache picks the site from the name the browser asks for (the HTTP `Host` header). The usual choice |
| **IP-based** | Each website has its **own IP address** |

## Install and Start

```bash
dnf install httpd -y
systemctl enable --now httpd
firewall-cmd --permanent --add-service={http,https} && firewall-cmd --reload
```

| Path | Holds |
|---|---|
| `/var/www/html/` | The default document root: put your pages here |
| `/etc/httpd/conf/httpd.conf` | The main configuration |
| `/etc/httpd/conf.d/*.conf` | Extra configuration files, loaded automatically: the place for your virtual hosts |
| `/usr/share/doc/httpd-core/httpd-vhosts.conf` | A sample virtual host file |
| `/var/log/httpd/` | `access_log` and `error_log` |

## One Website

```bash
echo "<h1>Welcome to sysops.local</h1>" > /var/www/html/index.html
curl http://localhost
```

Apache serves any file type (HTML, images, CSS, JavaScript, downloads); dynamic pages need a module or application server such as PHP.

## Name-Based Virtual Hosts

Start from the sample file:

```bash
cp /usr/share/doc/httpd-core/httpd-vhosts.conf /etc/httpd/conf.d/vhosts.conf
vi /etc/httpd/conf.d/vhosts.conf
```

Replace its examples with one `<VirtualHost>` block (a "container") per site:

```apache
<VirtualHost *:80>
    ServerName   sysops.local
    DocumentRoot /var/www/html
</VirtualHost>

<VirtualHost *:80>
    ServerName   cloudops.local
    DocumentRoot /opt/cloudops
</VirtualHost>

<Directory /opt/cloudops>
    Require all granted
</Directory>
```

The second site lives outside `/var/www`, so Apache needs a **`<Directory>`** block granting access to it (`/var/www` is already allowed in `httpd.conf`). Without it you get **403 Forbidden**.

```bash
mkdir -p /opt/cloudops
echo "<h1>Welcome to cloudops.local</h1>" > /opt/cloudops/index.html
chcon -R -t httpd_sys_content_t /opt/cloudops    # SELinux label (topic 06)
apachectl configtest                             # "Syntax OK"
systemctl reload httpd
```

Without DNS, map the names in `/etc/hosts` on the client (or the server itself):

```text
192.168.56.10   sysops.local   cloudops.local
```

Now `http://sysops.local` and `http://cloudops.local` show different pages from the same IP. Opening the site **by IP** shows the **first** virtual host, which acts as the default.

## How a Request Is Served

1. You type `sysops.local` in the browser.
2. The name is resolved to an IP (from `/etc/hosts`, then DNS).
3. The browser connects to that IP on port 80 and sends `Host: sysops.local`.
4. Apache finds the `<VirtualHost>` whose `ServerName` matches, and serves the file from its `DocumentRoot`.

## Questions

1. The second site returns 403 Forbidden. Name two possible causes.
2. Why does visiting the server's IP always show the same site?

<details>
<summary>Answers</summary>

1. A missing `<Directory ... Require all granted>` block, or the wrong SELinux label on the folder (fix with `chcon` or `semanage fcontext` plus `restorecon`).
2. Requests without a matching `ServerName` go to the first virtual host, the default.
</details>
