# 03. FTP with vsftpd

**FTP** (File Transfer Protocol) lets clients upload and download files.

| Fact | Detail |
|---|---|
| Ports | **21** (control: commands) and **20** (data, in active mode) |
| Transport | TCP |
| Login | Local users, an anonymous user, or virtual users |
| Security | Plain FTP sends passwords and files **unencrypted**. Use FTPS (FTP over TLS) or SFTP |

FTP server programs:

| Server | Notes |
|---|---|
| **vsftpd** | "Very Secure FTP Daemon", the RHEL default |
| ProFTPD | Flexible, Apache-like configuration |
| wu-ftpd | Washington University FTP daemon; historic |

**SFTP** is a different protocol: file transfer over **SSH** (port 22), built into `sshd`, with nothing extra to install. It is the best choice when both sides support it.

## Install and Start

```bash
dnf install vsftpd -y
systemctl enable --now vsftpd
ss -tulnp | grep -i vsftpd      # listening on port 21
nc -zv <server-ip> 21           # from a client
firewall-cmd --permanent --add-service=ftp && firewall-cmd --reload
```

Never stop the firewall to "fix" a connection: add the service instead.

```bash
systemctl list-units --type=service          # running services
systemctl list-unit-files --type=service     # all installed services
```

## Configuration

The main file is **`/etc/vsftpd/vsftpd.conf`**. Anonymous users see **`/var/ftp`**.

On RHEL 9 the defaults are `anonymous_enable=NO` and `local_enable=YES`: clients must log in with a local user's name and password. To allow anonymous downloads:

```text
anonymous_enable=YES
```

After editing any configuration file, restart (or reload) the service so the running program reads the new settings:

```bash
systemctl restart vsftpd
```

### Three Kinds of FTP Users

| Type | Logs in as |
|---|---|
| **Anonymous** | `anonymous` or `ftp`, no real password |
| **Local** | A real Linux account |
| **Virtual** | An account that exists only for FTP (mapped to one guest Linux user) |

## Using the FTP Client

```bash
dnf install ftp
ftp server1
```

| Command | Action |
|---|---|
| `help` | List the commands |
| `ls`, `cd` | Browse the server |
| `get file` / `mget *.txt` | Download one / many files |
| `put file` / `mput *.txt` | Upload one / many files |
| `bye` | Disconnect |

## FTP Users at Enterprise Level

Give each FTP customer their own storage and an account that can **only** use FTP:

1. Create and mount a partition for the data, for example `/data` (RHEL Fundamentals, topics 07 and 08).
2. Create the user with no shell:

```bash
useradd -d /data/ftpuser1 -s /sbin/nologin ftpuser1
passwd ftpuser1
```

3. **Jail** users in their home directories so they can't browse the rest of the system:

```text
chroot_local_user=YES
allow_writeable_chroot=YES
```

4. Send the user their credentials securely.

> 💡 Users with `/sbin/nologin` may be refused by PAM. If logins fail, make sure `/sbin/nologin` is listed in `/etc/shells`.

A complete sample configuration for **virtual users** with TLS is in [`configs/vsftpd-virtual-users.conf`](configs/vsftpd-virtual-users.conf).

## Active vs Passive FTP

FTP uses two connections: **control** (commands) and **data** (file contents). They differ in who opens the data connection.

| | Active FTP | Passive FTP |
|---|---|---|
| **Control connection** | Client to server port 21 | Client to server port 21 |
| **Data connection** | Server connects **back** to the client | Client connects to the server |
| **Server data port** | 20 | A random high port (above 1023), announced by the server |
| **Firewalls and NAT** | Often blocked: the client's firewall rejects the incoming connection | Friendly: the client opens every connection |
| **Used in** | Older setups | Modern setups, the usual default |

For passive mode behind a firewall, fix the port range in `vsftpd.conf` (`pasv_min_port`, `pasv_max_port`) and open the same range in the firewall.

## Questions

1. Users connect, but every listing hangs. The server is behind a firewall. What is likely wrong?
2. Create an account `reports` that can upload by FTP but never get a shell.

<details>
<summary>Answers</summary>

1. The passive data ports aren't open. Set `pasv_min_port`/`pasv_max_port` and allow that range (`firewall-cmd --permanent --add-port=30000-30010/tcp`).
2. `useradd -s /sbin/nologin reports && passwd reports`, with `local_enable=YES` and `write_enable=YES` in `vsftpd.conf`.
</details>
