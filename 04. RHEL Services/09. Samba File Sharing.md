# 09. Samba File Sharing

**Samba** shares files and printers between Linux and **Windows** (and Linux to Linux), using the Windows **SMB** protocol (also called **CIFS**). Unlike NFS, it always asks for a username and password.

| Port | Used by |
|---|---|
| 137, 138 (UDP) | NetBIOS name service and datagrams (`nmb`) |
| 139 (TCP) | NetBIOS session service (`smb`) |
| 445 (TCP) | SMB directly over TCP (modern clients) |

## Install and Start

```bash
dnf install samba samba-client -y
systemctl enable --now smb nmb
firewall-cmd --permanent --add-service=samba && firewall-cmd --reload
```

## Define a Share

The configuration file is **`/etc/samba/smb.conf`**. Add a section at the end; its name in brackets is the **share** name:

```ini
[common]
    path = /opt/fileserver
    hosts allow = 192.168.0.0/24
    browseable = yes
    writable = yes
    read only = no
    create mask = 0644
    directory mask = 0770
    valid users = sara, bilal
    read list = sara
    write list = bilal
```

| Setting | Meaning |
|---|---|
| `path` | The folder to share |
| `hosts allow` | Which networks may connect |
| `browseable` | Show the share when clients browse the server |
| `writable` / `read only = no` | Allow writing |
| `create mask` / `directory mask` | Permissions for new files / directories |
| `valid users` | Who may connect |
| `read list` / `write list` | Users limited to reading / allowed to write |
| `force user` | Make every file owned by one Linux user |

Check the configuration, like `exportfs` for NFS:

```bash
testparm                     # check syntax and show the active settings
testparm -v | grep -i mask   # every setting, including defaults, filtered
```

Prepare the folder, including its SELinux label:

```bash
mkdir -p /opt/fileserver
chcon -R -t samba_share_t /opt/fileserver
systemctl restart smb
```

## Samba Users

Every Linux user can log in with FTP and has a mailbox by default, but **no Linux user is a Samba user** until you add them. Samba keeps its own password database:

```bash
useradd sara                 # must exist as a Linux user first
smbpasswd -a sara            # set her Samba password
pdbedit -L                   # list Samba users
```

## Connect

**From Windows:** open File Explorer (or press Win+R) and type `\\192.168.56.10\common`, then log in as `sara`.

**From Linux:**

```bash
smbclient -L //192.168.56.10 -U sara                       # list the shares
smbclient //192.168.56.10/common -U sara                   # FTP-like session
mount -t cifs //192.168.56.10/common /mnt -o username=sara # mount it (cifs-utils package)
```

## Workgroups, Domains and Samba's Role

- A Windows **workgroup** is a peer-to-peer network: computers share files and printers with no central authority.
- A **domain** has a central server (Windows **Active Directory**) that manages users, logins and permissions.
- **Samba** bridges the two worlds by speaking SMB/CIFS. Its daemons are **`smbd`** (file and printer sharing) and **`nmbd`** (NetBIOS name resolution and browsing, so Windows machines can find the Linux shares by name). NFS has no such Windows integration, which is why Samba is the tool for sharing with Windows.
- **Samba 4** can join an Active Directory domain (with **winbind**, which authenticates users against AD) or even act as an AD domain controller itself, though not every AD feature is covered in large enterprises.

## Questions

1. A Windows user gets "access denied" although the Linux account exists. What is missing?
2. The share is visible but empty, and SELinux is enforcing. What do you check?

<details>
<summary>Answers</summary>

1. The Samba password: `smbpasswd -a <user>`.
2. The folder's label: it must be `samba_share_t` (`ls -Zd /opt/fileserver`; fix with `chcon` or `semanage fcontext` plus `restorecon`).
