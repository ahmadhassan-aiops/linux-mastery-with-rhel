# 06. SELinux

**SELinux** (Security-Enhanced Linux) adds **mandatory access control** on top of normal file permissions. Every process, file and port carries a **label**, and a policy says which labels may access which. Even if an attacker takes over Apache, SELinux stops it reading files that aren't labelled as web content, such as `/etc/shadow` or users' home directories.

## Modes

| Mode | Effect |
|---|---|
| **Enforcing** | The policy is applied: violations are blocked and logged. The RHEL default |
| **Permissive** | Nothing is blocked, but violations are logged. For troubleshooting |
| **Disabled** | SELinux is off: no protection, no labelling |

```bash
getenforce                 # Enforcing, Permissive or Disabled
sestatus                   # full status
setenforce 0               # switch to permissive now (until reboot)
setenforce 1               # back to enforcing
```

`setenforce` switches between enforcing and permissive without a reboot. The boot-time mode is set in **`/etc/selinux/config`** (`SELINUX=enforcing`). Disabling or re-enabling SELinux requires a **reboot**, and re-enabling it relabels the whole file system. On RHEL 9, disable it with the kernel parameter `selinux=0` rather than the config file, but think twice: fixing the label or boolean is almost always the right answer.

## Booleans: Switches for Services

**Booleans** are on/off switches that change the policy for a service without writing rules.

```bash
getsebool -a                               # every boolean
getsebool -a | grep httpd                  # booleans for Apache
setsebool -P httpd_can_network_connect on  # allow Apache to make network connections
setsebool -P samba_enable_home_dirs on     # allow Samba to share home directories
```

`-P` makes the change permanent.

## Contexts: Labels on Files and Processes

```bash
ls -Z /var/www/html          # file contexts: system_u:object_r:httpd_sys_content_t:s0
ls -Zd /var/www              # a directory's own context
ps -eZ | grep httpd          # process contexts: httpd_t
```

The important part is the **type** (`httpd_sys_content_t`). Apache (`httpd_t`) may read files of that type.

### Fixing Labels

Files created elsewhere and then **moved** keep their old label, which is a common cause of "403 Forbidden" or "permission denied" even when `rwx` looks fine.

```bash
restorecon -Rv /var/www/html                         # reset to the default labels
chcon -R -t httpd_sys_content_t /opt/cloudops        # change a label (temporary: lost on relabel)
semanage fcontext -a -t httpd_sys_content_t "/opt/cloudops(/.*)?"   # make it permanent
restorecon -Rv /opt/cloudops
```

### Ports

Services may only listen on ports labelled for them:

```bash
semanage port -l | grep ssh                       # ssh_port_t   tcp   22
semanage port -a -t ssh_port_t -p tcp 2222        # allow sshd on 2222
```

## Troubleshooting

```bash
ausearch -m AVC -ts recent      # recent denials
journalctl -t setroubleshoot    # human-readable explanations (setroubleshoot-server package)
sealert -a /var/log/audit/audit.log
```

Switching to permissive tells you whether SELinux is the cause; then fix the label, boolean or port and switch back to enforcing.

## Questions

1. Apache shows 403 for files in `/var/www/html` that you moved there from `/root`. Permissions are `644`. What is the fix?
2. Is it safe to leave a server in permissive mode?

<details>
<summary>Answers</summary>

1. The files kept the `admin_home_t` label from `/root`. Run `restorecon -Rv /var/www/html`.
2. No: nothing is enforced, so SELinux gives no protection. Use permissive only briefly, to diagnose.
