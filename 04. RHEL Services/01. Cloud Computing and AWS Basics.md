# 01. Cloud Computing and AWS Basics

**Cloud computing** is renting IT resources (servers, storage, networks, software) from a provider over the internet, on demand, instead of owning them.

## On-Premises vs Co-location vs Cloud

| | On-premises | Co-location | Cloud |
|---|---|---|---|
| **What it is** | Your own hardware in your own building | Your own hardware in a rented data-centre space | The provider's hardware, used over the internet |
| **You provide** | Servers, storage, network (routers, switches, firewalls), power, cooling, security, software and monitoring (Nagios, Zabbix, Prometheus) | Servers, storage, network gear and software | Only your configuration and data |
| **Provider gives** | Nothing | Space, power, cooling, physical security, connectivity | Everything below the level you choose (IaaS, PaaS or SaaS) |
| **Upfront cost** | High: hardware and the building | Moderate: hardware only | Low: nothing to buy |
| **Running cost** | Power, cooling, staff | Monthly fees, plus "remote hands" services | Pay as you go: compute, storage, data transfer |
| **Time to go live** | Months (procurement, installation) | Weeks to months | Minutes to hours |
| **Maintenance** | All yours: high complexity | Shared: provider handles the facility | Mostly the provider's |

## IaaS, PaaS and SaaS

| Model | You get | You manage | Examples |
|---|---|---|---|
| **IaaS** (Infrastructure) | Virtual machines, storage, networks, load balancers, firewalls | The OS and everything on it | AWS EC2, Azure VMs |
| **PaaS** (Platform) | A managed OS, runtime, database or web server | Your application and data | AWS Elastic Beanstalk, RDS, Azure App Service |
| **SaaS** (Software) | A complete application | Only your use of it | Gmail, Microsoft 365, Salesforce |

## Launching an EC2 Instance

In AWS a virtual machine is an **EC2 instance** (Elastic Compute Cloud).

1. Open the AWS Console and choose a **region** (top right). Your account starts in one, but you can use any region in the world; choose one close to your users.
2. **EC2 → Launch instance:** pick an AMI (for example Red Hat Enterprise Linux or Rocky Linux), an instance type, a key pair and a security group allowing SSH from your IP.
3. Connect from your PC with SSH, PuTTY or **MobaXterm**:

```bash
ssh -i mykey.pem ec2-user@<public-ip>
```

Also worth knowing in the console: **Billing** (set a budget alert first!), the **Support Center**, and **CloudWatch**, AWS's monitoring service.

## Instance Families

| Family | Optimized for | Examples |
|---|---|---|
| **General purpose** | Balanced CPU, memory and network | T3, T4g, M6i, M7g |
| **Compute optimized** | CPU-heavy work: batch jobs, web servers, gaming | C6i, C7g |
| **Memory optimized** | Large databases, in-memory caches | R6i, R7g, X2idn |
| **Accelerated computing** | GPUs and AI chips: machine learning, graphics | P4d, P5, G5, Inf2 |
| **Storage optimized** | Very fast local disks: data warehouses, NoSQL | I4i, D3 |

Names read as family + generation + options: `m7g.large` is general purpose, 7th generation, Graviton (ARM) processor, large size. Current types: https://aws.amazon.com/ec2/instance-types/

## Storage: EBS, EFS and S3

| Service | Type | Like | Attached to |
|---|---|---|---|
| **EBS** (Elastic Block Store) | **Block** storage | A virtual hard disk (`/dev/xvda`, `/dev/nvme0n1`) | One EC2 instance in the same Availability Zone |
| **EFS** (Elastic File System) | **File** storage | An NFS share | Many instances at once |
| **S3** (Simple Storage Service) | **Object** storage | Google Drive or OneDrive for applications | Nothing: accessed over HTTPS from anywhere |

EBS volume types: https://docs.aws.amazon.com/ebs/latest/userguide/ebs-volume-types.html

### S3 in Practice

- Data is stored as **objects** (a file plus metadata) inside **buckets**, unstructured.
- Create a bucket in the S3 console, then upload files.
- Buckets are **private by default**. To share one file, use a **pre-signed URL**; make objects public only when you really must, by turning off Block Public Access and adding a bucket policy.
- Storage classes trade price for access speed (Standard, Intelligent-Tiering, Glacier): https://aws.amazon.com/s3/storage-classes/
- Check the current AWS Free Tier terms before relying on free storage.

## Public IP and Elastic IP

- An instance has a **private IP** inside its VPC. Running `ip a` on it shows only that address.
- AWS maps a **public IP** to it at the internet gateway with **NAT** (network address translation). Find it from the instance:

```bash
curl ifconfig.me
dig +short myip.opendns.com @resolver1.opendns.com
```

- Machines in the same network talk to each other using **private** IPs.
- The automatic public IP is released when you **stop** the instance, and a different one is assigned when it starts again (a simple reboot keeps it).
- An **Elastic IP** is a static public address you allocate and associate with the instance: it survives stops and starts, so DNS records and firewall rules keep working.

> 💸 AWS charges for every public IPv4 address, including Elastic IPs. Release the ones you don't use.

## Questions

1. A company needs a database server live by tomorrow, and the workload is unpredictable. On-premises, co-location or cloud?
2. Which storage service would you use for a disk that holds an instance's database files?
3. After stopping and starting an instance, your SSH command fails. Why, and how do you prevent it?

<details>
<summary>Answers</summary>

1. Cloud: ready in minutes and pay-as-you-go suits variable load.
2. EBS (block storage attached to the instance).
3. The public IP changed. Associate an Elastic IP (and update DNS to point to it).
</details>
