# 05. TCP Wrappers, iptables and firewalld

## TCP Wrappers (Legacy)

**TCP Wrappers** was a simple access filter for network services such as SSH, FTP and telnet. Rules in two files decided who could connect:

| File | Purpose | Example |
|---|---|---|
| `/etc/hosts.allow` | Allowed clients | `sshd: 192.168.1.0/255.255.255.0` |
| `/etc/hosts.deny` | Denied clients | `ALL: ALL` |

Only programs linked with the **libwrap** library obeyed these files. Check a binary with `ldd`:

```bash
ldd /usr/sbin/vsftpd | grep libwrap
```

> ⚠️ TCP Wrappers was **removed in RHEL 8**. On RHEL 8 and 9, use firewalld and each service's own access settings instead. You'll still meet it on RHEL 6 and 7 systems.

## Firewalls

A **firewall** allows or blocks network traffic based on rules.

| Kind | Examples |
|---|---|
| **Kernel (software) firewalls on Linux** | `iptables` (RHEL 6), `firewalld` with nftables (RHEL 7 and later) |
| **Hardware firewalls** for whole networks | Fortinet FortiGate, Palo Alto, Cisco ASA, Juniper SRX, SonicWall, Sophos (formerly Cyberoam) |
| **Open-source firewall appliances** | pfSense, OPNsense, IPFire (a successor to IPCop) |

Hardware firewalls add VPNs, intrusion prevention and higher throughput for large networks.

## iptables

`iptables` writes rules into **netfilter**, the packet-filtering framework inside the Linux kernel. Netfilter checks every packet against those rules and accepts, drops or modifies it.

### Chains

| Chain | Handles |
|---|---|
| **INPUT** | Packets coming **to** this machine |
| **OUTPUT** | Packets leaving **from** this machine |
| **FORWARD** | Packets passing **through** it (routers, gateways) |

### Tables

| Table | Used for |
|---|---|
| `filter` | Allowing and blocking: the default table |
| `nat` | Changing addresses (NAT, port forwarding) |
| `mangle` | Modifying packet headers |
| `raw` | Exempting packets from connection tracking |

```bash
iptables -L -n --line-numbers      # rules in the filter table, numbered
iptables -t nat -L -n              # rules in another table
```

### First Match Wins

Rules are checked **from top to bottom**. The first rule that matches a packet decides its fate, and the rest are skipped. Order matters: an "allow SSH" rule below a "reject everything" rule never fires.

### Building a Firewall

> ⚠️ On a remote server, a wrong rule locks you out. Work from the console, or schedule an automatic flush (`echo "iptables -F; iptables -P INPUT ACCEPT; iptables -P OUTPUT ACCEPT" | at now + 5 minutes`) while you test.

```bash
# Allow traffic that belongs to connections we already accepted
iptables -A INPUT  -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Allow the loopback interface
iptables -A INPUT -i lo -j ACCEPT

# Allow HTTP from anywhere
iptables -A INPUT -p tcp --dport 80 -j ACCEPT

# Allow SSH only from one admin machine
iptables -A INPUT -s 192.168.0.105/32 -p tcp --dport 22 -j ACCEPT

# Allow ping (ICMP echo request is type 8, the reply is type 0)
iptables -A INPUT -p icmp --icmp-type 8 -j ACCEPT

# Default policy: drop everything else
iptables -P INPUT DROP
iptables -P FORWARD DROP
```

| Option | Meaning |
|---|---|
| `-A INPUT` | Append a rule to the INPUT chain |
| `-s 0/0` | Source address: `0/0` means any address |
| `-p tcp --dport 80` | Protocol and destination port |
| `-j ACCEPT` / `DROP` / `REJECT` | Allow / silently discard / refuse with an error message to the sender |
| `-P INPUT DROP` | The chain's default **policy** for packets no rule matched |

Blocking everything coming in:

```bash
iptables -P INPUT DROP                      # silently
iptables -A INPUT -s 0/0 -j REJECT          # or reject, so senders get "destination unreachable"
```

Setting `OUTPUT` to `DROP` as well blocks the server's own replies and updates, so allow `ESTABLISHED` traffic and the outbound services you need first.

### Removing Rules and Saving

```bash
iptables -D INPUT 3          # delete rule number 3 of INPUT
iptables -F                  # flush: delete every rule (policies stay)
iptables-save > /etc/sysconfig/iptables      # save (iptables-services package)
iptables-restore < /etc/sysconfig/iptables   # load
```

Rules made with the `iptables` command live in memory and vanish at reboot unless saved.

## firewalld (RHEL 7, 8 and 9)

**firewalld** is the standard firewall from RHEL 7, using **nftables** underneath from RHEL 8. Instead of individual rules, you assign interfaces to **zones** and allow **services** in each zone.

```bash
systemctl status firewalld
firewall-cmd --state
firewall-cmd --get-zones                 # block, dmz, drop, external, home, internal, public, trusted, work
firewall-cmd --get-default-zone          # usually public
firewall-cmd --list-all                  # what the default zone allows
firewall-cmd --list-all-zones            # details of every zone
firewall-cmd --get-services              # every service name firewalld knows
```

### Allowing Services and Ports

```bash
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=nfs
firewall-cmd --permanent --add-port=8080/tcp
firewall-cmd --permanent --remove-service=ftp
firewall-cmd --reload                    # apply the permanent configuration now
firewall-cmd --list-services
```

`--permanent` writes the change to disk, and `--reload` loads it. Without `--permanent`, a change applies immediately but is lost at the next reload or reboot.

Block everything at once by switching the default zone:

```bash
firewall-cmd --set-default-zone=block
```

### Stateful vs Stateless

firewalld is **stateful**: once you allow incoming traffic to a service, the replies are allowed automatically. With plain iptables you write the `ESTABLISHED` rules yourself.

In AWS the same idea applies: **security groups** are stateful, while **network ACLs** (NACLs) are stateless and need rules in both directions.

## Questions

1. With iptables, you appended "allow SSH" after "reject all". SSH is still blocked. Why?
2. Open port 5432 (PostgreSQL) permanently with firewalld.
3. Which iptables chain filters packets that a Linux router forwards between two networks?

<details>
<summary>Answers</summary>

1. The first matching rule wins, and "reject all" comes first. Insert the SSH rule above it (`iptables -I INPUT 1 ...`).
2. `firewall-cmd --permanent --add-port=5432/tcp && firewall-cmd --reload` (or `--add-service=postgresql`).
3. FORWARD.
</details>
