# 01. What Is Linux

**Linux** is a family of free, open-source operating systems built on the **Linux kernel**, the core program that manages the CPU, memory, disks and devices. Anyone may download, study, modify and share the kernel, and any operating system that runs on it can call itself Linux.

## Why Learn Linux?

| Reason | What it means for you |
|---|---|
| **It runs the world's servers** | Cloud platforms, web servers, databases, Kubernetes clusters and supercomputers run mostly on Linux |
| **Free and open source** | No licence cost, and the source code is public |
| **Secure and reliable** | A strict permission model, fast security updates, and servers that run for years without a reboot |
| **Revives older computers** | Lightweight distributions run well on old hardware |
| **Made for programmers** | Powerful shell, scripting, compilers and package managers out of the box |
| **Customizable** | Change anything from the desktop to the kernel itself |
| **Huge community** | Forums, documentation and answers for almost every problem |
| **Privacy** | No forced telemetry or advertising in community distributions |

## Where Linux Is Used

- **Servers and cloud:** AWS, Azure and Google Cloud virtual machines, containers and Kubernetes.
- **Smartphones:** Android is built on a modified Linux kernel.
- **Embedded and IoT:** routers, smart TVs, e-readers, cars, drones and robots.
- **AI and data science:** GPU servers, deep learning frameworks and HPC clusters.
- **Space and science:** satellites, rockets and research labs.
- **Security:** penetration-testing distributions such as Kali Linux and Parrot OS.

## Unix vs Linux

| | Unix | Linux |
|---|---|---|
| Origin | Bell Labs, 1969 | Linus Torvalds, 1991 |
| Licence | Mostly proprietary (AIX, HP-UX, Solaris) | Free and open source (GPL) |
| Hardware | Usually tied to the vendor's machines | Runs on almost anything |
| Relationship | The original design | A Unix-like system written from scratch, not derived from Unix code |

## Distributions

A **distribution (distro)** packages the Linux kernel with tools, a package manager and often a desktop. Browse them at https://distrowatch.com.

| Family | Examples | Package format | Support |
|---|---|---|---|
| **Red Hat** | RHEL, CentOS Stream, Rocky Linux, AlmaLinux, Fedora | `.rpm` (dnf/yum) | RHEL is commercial; the others are community |
| **Debian** | Debian, Ubuntu, Linux Mint, Kali | `.deb` (apt) | Ubuntu is free with commercial support from Canonical |
| **SUSE** | SLES, openSUSE | `.rpm` (zypper) | Commercial and community |

This course focuses on **RHEL** (Red Hat Enterprise Linux) and its free relatives, the standard in enterprise data centres. Most commands work the same on every distribution; a few, mainly package management, differ.

## The Command Line

Most desktop users work in a **GUI** (graphical user interface). Linux administrators work mainly in the **CLI** (command line interface): a prompt where you type commands.

- Servers usually have **no GUI at all**.
- The CLI keeps working when the graphical system breaks.
- Commands can be scripted and automated, which is the heart of DevOps.

Learning Linux comes down to two things:

1. **Concepts:** how the system works (files, users, processes, permissions).
2. **Commands:** how to act on those concepts.

> 💡 When a command behaves differently on your distribution, the built-in documentation is the authority: `man <command>`, `<command> --help` and `apropos <keyword>`.
