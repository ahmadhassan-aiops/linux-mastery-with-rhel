# 06. Users, Groups and sudo

Linux is a multi-user system. Every file and process belongs to a **user**, and users are collected into **groups**.

| Kind of user | Description |
|---|---|
| **Standard user** | Basic permissions: their own home directory and files |
| **root** | The administrator, with full control. What makes root special is its **user ID: 0** |

## Creating and Removing Users

```bash
useradd omar                                   # create a user
useradd -m omar                                # make sure a home directory is created
useradd -m -s /bin/bash omar                   # also set the login shell
useradd -c "Omar Farooq" -m -s /bin/bash omar  # add the full name as a comment
passwd omar                                    # set the password (needed to log in)
```

> 💡 On RHEL, `useradd` creates the home directory by default (`CREATE_HOME yes` in `/etc/login.defs`). On Debian and Ubuntu it does not, so use `-m` there.

```bash
usermod -L omar                 # lock the account (nobody can log in as omar)
usermod -U omar                 # unlock it
usermod -c "New full name" omar # change the comment
userdel omar                    # delete the user, keep the home directory
userdel -r omar                 # delete the user, home directory and mail spool
```

## su vs sudo

| Command | What it does |
|---|---|
| `su` | **Switches** to another user (root by default). You need *that user's* password |
| `su - ahmad` | Switch to ahmad with a full login environment |
| `sudo command` | Runs **one command** as root. You type *your own* password, and you must be allowed in `/etc/sudoers` |

Switching between users (recorded):

```text
[ahmad@localhost ~]$ su
Password:
[root@localhost ahmad]# su ahmad
[ahmad@localhost ~]$
```

### Without sudo Rights

A normal user can't read root-only files (recorded):

```text
[ahmad@localhost ~]$ sudo cat /etc/sudoers
cat: /etc/sudoers: Permission denied
```

### Granting sudo Rights

Edit the sudoers file **with `visudo`**, which checks the syntax before saving (a broken sudoers file can lock everyone out of sudo):

```bash
visudo
```

Add a line under the root entry:

```text
## Allow root to run any commands anywhere
root    ALL=(ALL)       ALL
ahmad   ALL=(ALL)       ALL
```

On RHEL, the simpler way is to add the user to the **wheel** group, which already has sudo rights:

```bash
usermod -aG wheel ahmad
```

Now ahmad can read the file (recorded, first lines):

```text
[ahmad@localhost ~]$ sudo cat /etc/sudoers
## Sudoers allows particular users to run various commands as
## the root user, without needing the root password.
##
## Examples are provided at the bottom of the file for collections
## of related commands, which can then be delegated out to particular
## users or groups.
##
## This file must be edited with the 'visudo' command.
```

> 🔐 The original lab used `NOPASSWD:ALL`, which lets the user become root without any password. Avoid it on real servers: if that account is compromised, the attacker is root immediately.

A user who is **not** in sudoers is refused, and the attempt is logged (recorded):

```text
[sara@localhost ahmad]$ sudo cat /etc/sudoers

We trust you have received the usual lecture from the local System
Administrator. It usually boils down to these three things:

    #1) Respect the privacy of others.
    #2) Think before you type.
    #3) With great power comes great responsibility.

For security reasons, the password you type will not be visible.

[sudo] password for sara:
sara is not in the sudoers file.
```

## Groups

Every group is a line in `/etc/group`: `name:password:GID:members`. Count them (recorded):

```text
[root@localhost ahmad]# cat /etc/group | wc -l
61
```

### Create a Group and Add Members

Recorded (the middle of the 61-line file is trimmed):

```text
[root@localhost ahmad]# groupadd devops
[root@localhost ahmad]# cat /etc/group
root:x:0:
bin:x:1:
...
wheel:x:10:ahmad
...
ahmad:x:1000:
sara:x:1001:
docker:x:981:
devops:x:1002:
```

```text
[root@localhost ahmad]# usermod -G devops ahmad
[root@localhost ahmad]# usermod -G devops sara
[root@localhost ahmad]# getent group devops
devops:x:1002:ahmad,sara
```

> ⚠️ `usermod -G` **replaces** a user's secondary groups. Before this command `/etc/group` showed `wheel:x:10:ahmad`; afterwards it showed `wheel:x:10:`, so ahmad silently lost his sudo rights. Always use **`usermod -aG devops ahmad`** (`-a` = append).

### Remove Members and Delete the Group

`gpasswd -d` removes a user from a group (recorded):

```text
[root@localhost ahmad]# gpasswd -d ahmad devops
Removing user ahmad from group devops
[root@localhost ahmad]# gpasswd -d sara devops
Removing user sara from group devops
[root@localhost ahmad]# getent group devops
devops:x:1002:
```

```bash
gpasswd -a ahmad devops   # the opposite: add a user to a group
groupdel devops           # delete the group
id ahmad                  # a user's UID, primary group and all groups
```

## Practice

1. Create the users `bilal` and `zara` with home directories and bash as their shell.
2. Create the group `developers` and add both users **without** removing them from other groups.
3. Give `bilal` sudo rights the RHEL way, then lock `zara`'s account.

<details>
<summary>Solution</summary>

```bash
useradd -m -s /bin/bash bilal && passwd bilal
useradd -m -s /bin/bash zara && passwd zara
groupadd developers
usermod -aG developers bilal
usermod -aG developers zara
usermod -aG wheel bilal
usermod -L zara
id bilal; id zara
```
</details>
