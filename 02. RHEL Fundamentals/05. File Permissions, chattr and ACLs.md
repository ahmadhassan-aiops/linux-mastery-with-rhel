# 05. File Permissions, chattr and ACLs

## What r, w and x Really Mean

**On a file**

- **Read:** open and view it. You can even edit it in vim, but without write permission you can't save the changes.
- **Write:** modify its contents.
- **Execute:** run it as a program or script.

**On a directory**

- **Read:** list the names of files inside it.
- **Write:** create, delete and rename files inside it.
- **Execute:** enter it (`cd`) and access the files within.

> 💡 **Deleting a file depends on the directory, not on the file.** A file with permissions `000` can still be deleted by any user who has write and execute permission on the directory that contains it (and root can always delete it). That is why a parent directory's `w` lets its owner remove or overwrite files inside, even files they can't write to (vim's `:wq!` does exactly that: it replaces the file).

## Octal Notation

| Permission | Value |
|---|---|
| read `r` | 4 |
| write `w` | 2 |
| execute `x` | 1 |

Add the values for each of user, group and others:

| Number | Permissions | Number | Permissions |
|---|---|---|---|
| 7 | `rwx` (4+2+1) | 4 | `r--` |
| 6 | `rw-` (4+2) | 3 | `-wx` |
| 5 | `r-x` (4+1) | 0 | `---` |

Output (captured on a Linux machine):

```text
$ chmod 754 script.sh
$ ls -l script.sh
-rwxr-xr-- 1 root root 0 Oct 21 19:10 script.sh
$ stat -c '%A %a %n' script.sh
-rwxr-xr-- 754 script.sh
```

Apply permissions to a directory and everything in it with `-R` (recursive), and `-v` (verbose) to list each change:

```bash
chmod -Rv 750 /opt/project
```

There are online "chmod calculators", but the 4-2-1 rule is all you need.

## chattr: Protection Even from root

`chattr` (change attribute) sets file-system attributes that override normal permissions.

```bash
chattr +i important.conf     # immutable: nobody, not even root, can modify, delete or rename it
lsattr important.conf        # shows ----i--------- important.conf
chattr -i important.conf     # remove the protection
chattr +a app.log            # append only: data can be added but not changed or removed
```

Great for protecting critical files such as `/etc/resolv.conf` from accidental changes.

## ACLs: Permissions for Specific Users

Normal permissions only know one owner and one group. **Access Control Lists** give extra users or groups their own permissions on a file.

```bash
setfacl -m u:sara:rwx report.txt     # -m modify: give sara rwx
setfacl -m g:devops:r report.txt     # give the devops group read
getfacl report.txt                   # show the ACL
setfacl -x u:sara report.txt         # remove sara's entry
setfacl -b report.txt                # remove all ACL entries
```

A file with an ACL shows a `+` at the end of its permissions in `ls -l`: `-rw-rwxr--+`.

## Questions

1. Convert `rwxr-x---` to octal.
2. What does `chmod 640 file` give the group?
3. A user can't `cd` into a directory although it has `r` for them. What is missing?
4. How do you let only the user `bilal` (not his group) write to `/data/app.conf` while keeping its owner and group?

<details>
<summary>Answers</summary>

1. `750`.
2. Read only (`4`).
3. Execute (`x`) permission on the directory.
4. `setfacl -m u:bilal:rw /data/app.conf`.
</details>
