# 10. Compression and Archiving

- **Compression** shrinks a file (called *deflating*).
- **Archiving** bundles many files into one.

| Tool | Compresses | Archives | Extension |
|---|---|---|---|
| `gzip` | ✅ | ❌ | `.gz` |
| `bzip2` | ✅ | ❌ | `.bz2` |
| `xz` | ✅ | ❌ | `.xz` |
| `zip` | ✅ | ✅ | `.zip` |
| `tar` | Only with a compression option | ✅ | `.tar`, `.tar.gz`, `.tar.bz2`, `.tar.xz` |

## Making Test Files

```bash
touch file{1..10}        # brace expansion: file1 ... file10
man ls > file1           # > writes (overwrites) a command's output into a file
date >> date.txt         # >> appends instead of overwriting
```

## gzip, bzip2 and xz

```bash
gzip file1               # file1 -> file1.gz (the original is replaced)
bzip2 file2              # file2 -> file2.bz2
xz file3                 # file3 -> file3.xz
gzip *                   # compress every file in the directory, one by one
gzip -k file1            # keep the original too

gunzip file1.gz          # decompress (or gzip -d)
bunzip2 file2.bz2
unxz file3.xz
```

### Which One Compresses Best?

Three copies of the same 3.9 MB text file, compressed with each tool (captured on a Linux machine):

```text
-rw-r--r-- 1 root root 3910119 Oct 21 19:10 file1
-rw-r--r-- 1 root root 3910119 Oct 21 19:10 file2
-rw-r--r-- 1 root root 3910119 Oct 21 19:10 file3
-rw-r--r-- 1 root root       0 Oct 21 19:10 empty.txt
```

After `gzip file1; bzip2 file2; xz file3; gzip empty.txt`:

```text
-rw-r--r-- 1 root root     30 Oct 21 19:10 empty.txt.gz
-rw-r--r-- 1 root root 484384 Oct 21 19:10 file1.gz
-rw-r--r-- 1 root root 366202 Oct 21 19:10 file2.bz2
-rw-r--r-- 1 root root 333320 Oct 21 19:10 file3.xz
```

| Tool | Size | Speed |
|---|---|---|
| gzip | 12.4% of the original | Fastest |
| bzip2 | 9.4% | Slower |
| xz | 8.5% | Slowest, best compression |

Notice that the **empty** file grew from 0 to 30 bytes: compression always adds a header. Compressing an already-compressed file again gains nothing.

How well a file compresses depends on its content: text shrinks a lot, while JPEG, MP4 or ZIP files barely shrink at all.

### Reading Compressed Files Without Extracting

A compressed file looks like binary garbage to `cat`. Use:

```bash
zcat file1.gz | head     # gzip
bzcat file2.bz2 | head   # bzip2
xzcat file3.xz | head    # xz
file file1.gz            # what type is it?
```

## zip

```bash
zip archive.zip *                   # archive and compress every file here
zip archive.zip file1 file2         # specific files
zip -r site.zip /var/www/html       # a directory, recursively
zip /opt/etc-backup.zip /etc/*      # from anywhere: source /etc, archive in /opt
zip archive.zip newfile             # add a file to an existing archive
zip -9 archive.zip bigfile          # -0 (store only) to -9 (maximum compression)

unzip -l archive.zip                # list the contents without extracting
unzip archive.zip                   # extract here
unzip archive.zip file1             # extract one file only
unzip archive.zip -d /tmp/out       # extract to a directory
```

`*` on its own means every file in the **current** directory; `/etc/*` means every file in `/etc`.

## tar

`tar` (tape archive) bundles files, keeping permissions and directory structure. Add `z`, `j` or `J` to compress at the same time.

| Option | Meaning |
|---|---|
| `c` | Create an archive |
| `x` | Extract |
| `t` | List the contents |
| `v` | Verbose: show each file |
| `f` | The archive file name follows |
| `z` / `j` / `J` | Compress with gzip / bzip2 / xz |
| `-C dir` | Extract into `dir` |

```bash
tar cvf backup.tar *                  # archive only
tar cvf backup.tar file1 file2        # specific files
tar tvf backup.tar                    # list
tar zcvf backup.tar.gz /etc           # archive + gzip
tar jcvf backup.tar.bz2 /etc          # archive + bzip2
tar Jcvf backup.tar.xz /etc           # archive + xz

tar xvf backup.tar                    # extract
tar zxvf backup.tar.gz                # extract a .tar.gz
tar jxvf backup.tar.bz2               # extract a .tar.bz2
tar xvf backup.tar.gz -C /restore     # modern tar detects the compression itself
```

## Questions

1. You must send 200 log files as one attachment, as small as possible. Which command?
2. How do you check what's inside `site.tar.gz` without extracting it?
3. Why might `gzip photo.jpg` save almost nothing?

<details>
<summary>Answers</summary>

1. `tar Jcvf logs.tar.xz *.log` (or `tar zcvf` if speed matters more).
2. `tar tzvf site.tar.gz`.
3. JPEG data is already compressed.
</details>
