# 11. Backups with rsync

## Backup Types

| Type | Copies | Restore needs |
|---|---|---|
| **Full** | Everything, every time | The last full backup |
| **Incremental** | Only what changed since the **last backup of any type** | The last full + every incremental since |
| **Differential** (also called cumulative) | Everything changed since the **last full** backup | The last full + the latest differential |

## Backup Tools

| Tool | Use |
|---|---|
| `cp -a` | Simple local copies (topic 02) |
| `tar` | Archives (topic 10) |
| **`rsync`** | Incremental copies, locally or to another server: the most important one |
| `scp` | Secure copy over SSH |
| `cpio` | Archive tool used in some system images |

Enterprise backup software includes Veritas NetBackup, Veeam, Dell EMC NetWorker and similar. Open-source options include Amanda, Bacula and BackupPC. Destinations are typically **LTO** (Linear Tape-Open) tape libraries, NAS or SAN storage.

## Why rsync?

`cp` copies everything again on every run. `rsync` compares the source with the destination and **copies only what changed**, which makes it the classic incremental backup tool. It can work over SSH to a remote machine, and reports what it did.

```bash
rsync -av /data/ /backup/data/          # the everyday form
```

| Option | Meaning |
|---|---|
| `-a` | **Archive**: recursive, and preserve permissions, owners, timestamps and links (implies `-rlptgoD`) |
| `-v` | Verbose: list the files |
| `-r` | Recursive only (without preserving attributes) |
| `-p` | Preserve permissions |
| `-z` | Compress data during the transfer (useful over a network) |
| `-c` | Compare files by **checksum** instead of size and time (slower, thorough) |
| `-n` | Dry run: show what would happen, change nothing |
| `--delete` | Delete files in the destination that no longer exist in the source, so both sides match exactly |
| `--progress` | Show progress for each file |

> 💡 The trailing slash matters: `rsync -a /data/ /backup/` copies the **contents** of `/data`; `rsync -a /data /backup/` creates `/backup/data`.

rsync doesn't compress what it stores. To keep compressed backups, combine it with `tar` or `zip`.

## How rsync Decides What to Copy

By default it compares each file's **size and modification time (mtime)**. If either differs, it copies the file (efficiently, sending only the changed parts over the network).

Check the timestamps with `stat`:

```bash
stat /backup/data/report.txt
```

| Timestamp | Changes when |
|---|---|
| **atime** (access) | The file is read |
| **mtime** (modify) | The contents change |
| **ctime** (change) | The contents **or** the metadata (owner, permissions) change |

## Backups to Another Server

```bash
rsync -avz /data/ ahmad@192.168.1.50:/backup/data/
```

You give the remote user and host, and rsync connects over SSH (it asks for the password, or uses an SSH key). For nightly backups, schedule the command with **cron** (RHEL Networking and Administration, topic 10) and set up SSH keys so no password is needed.

## Questions

1. The backup folder still has files that were deleted from the source weeks ago. Which option fixes that?
2. You want to see what a big rsync job would change before running it. How?
3. A Monday full backup is followed by daily incrementals. The disk fails on Thursday. What do you restore?

<details>
<summary>Answers</summary>

1. `--delete` (test it with `-n` first).
2. Add `-n` (dry run), e.g. `rsync -avn --delete /data/ /backup/data/`.
3. Monday's full backup, then Tuesday's and Wednesday's incrementals (and Thursday's, if it ran) in order.
</details>
