# 06. Run Levels, systemd Targets and Root Password Recovery

## Run Levels (RHEL 6 and Earlier)

A **run level** is the mode the system boots into. There are seven, numbered 0 to 6.

| Run level | Mode |
|---|---|
| 0 | Halt: the system can be powered off safely |
| 1 | Single-user mode (maintenance, root only, no network) |
| 2 | Multi-user without NFS (network file system) |
| 3 | Multi-user, text mode (command line, no GUI): the standard for servers |
| 4 | Unused, user-definable |
| 5 | Multi-user with a graphical desktop (GUI) |
| 6 | Reboot |

```bash
runlevel      # shows the previous and current run level, e.g. "N 5"
init 3        # switch to run level 3
```

- The default run level was set in **`/etc/inittab`** (usually 5 on desktops, 3 on servers).
- Setting the default to **6** makes the machine reboot forever, and **0** makes it shut down on every boot. To recover, interrupt the boot menu and pass a different run level to the kernel.

## systemd Targets (RHEL 7, 8 and 9)

From RHEL 7, **systemd** replaced the old init system, and **targets** replaced run levels.

| Run level | systemd target |
|---|---|
| 0 | `poweroff.target` |
| 1 | `rescue.target` |
| 3 | `multi-user.target` |
| 5 | `graphical.target` |
| 6 | `reboot.target` |

```bash
cat /etc/redhat-release                     # which RHEL version is this?
systemctl get-default                       # the default target
systemctl set-default multi-user.target     # boot to text mode from now on
systemctl set-default graphical.target      # boot to the desktop from now on
systemctl isolate multi-user.target         # switch now, like "init 3"
systemctl isolate graphical.target          # switch now, like "init 5"
```

## Virtual Consoles and Terminals

- In text mode there are **six virtual consoles**, `tty1` to `tty6`. Switch with `Alt+F1` to `Alt+F6` (from a graphical session: `Ctrl+Alt+F1` to `F6`).
- Each console keeps its own session, and you can work on all six at the same time.
- Terminal windows in GNOME and SSH sessions (PuTTY, MobaXterm) use **pseudo-terminals**: `/dev/pts/0`, `/dev/pts/1` and so on. There can be many hundreds of them.
- `tty` prints the terminal you are using; `w` lists everyone logged in and their terminals.
- `tty` comes from the old **teletypewriter** terminals.
- Need a desktop just once on a server that boots to text? `startx` starts the graphical session without changing the target (only if a desktop is installed).

## Reset a Forgotten root Password

### RHEL 7, 8 and 9

1. Reboot. When the **GRUB menu** appears, press `e` to edit the default entry.
2. Find the line starting with `linux` (`linux16` on RHEL 7) and add **`rd.break`** at its end.
3. Press `Ctrl+X` to boot. You land in an emergency shell before the real root file system is used.
4. Run:

```text
mount -o remount,rw /sysroot     # the real root is mounted read-only at /sysroot
chroot /sysroot                  # make it your root
passwd root                      # set the new password
touch /.autorelabel              # tell SELinux to relabel files on the next boot (required)
exit
exit
```

The first boot after this takes longer while SELinux relabels the file system.

### RHEL 6

At the boot menu press `a` (or `e`), add **`1`** (or `single`) to the kernel line and boot: the system starts in single-user mode as root, where you run `passwd root`.

### Protecting Single-User Mode

Anyone with access to the console could use these tricks, so:

- **RHEL 6:** in `/etc/sysconfig/init`, change `SINGLE=/sbin/sushell` to `SINGLE=/sbin/sulogin` so single-user mode asks for the root password.
- **RHEL 7 and later:** rescue mode already asks for the root password. Set a **GRUB password** (`grub2-setpassword`) to stop people editing the boot entry.
- If single-user mode is protected and the password is lost, boot from the **installation DVD or ISO** in rescue mode.

## Questions

1. A server should boot to the command line, not the desktop. What command do you run on RHEL 9?
2. Why is `touch /.autorelabel` needed after a password reset?
3. Which run level would you use to perform maintenance with no other users logged in?

<details>
<summary>Answers</summary>

1. `systemctl set-default multi-user.target`.
2. Changing `/etc/shadow` from the emergency shell leaves it with the wrong SELinux label, and the system would refuse logins.
3. Run level 1 (`rescue.target`).
