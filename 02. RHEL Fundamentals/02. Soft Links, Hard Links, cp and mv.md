# 02. Soft Links, Hard Links, cp and mv

## Inodes First

Every file has an **inode**: a record holding its permissions, owner, size, timestamps and the location of its data on disk. The file **name** is just a pointer from a directory to an inode. `ls -i` shows inode numbers.

## Hard Links and Soft Links

| | Hard link | Soft (symbolic) link |
|---|---|---|
| Create | `ln original.txt hard.txt` | `ln -s original.txt soft.txt` |
| Points to | The same **inode** as the original | The original's **name** (path) |
| Inode number | Same as the original | Its own |
| If the original is deleted | Still works: the data stays while any hard link remains | Breaks (a "dangling" link) |
| Across file systems/partitions | No | Yes |
| Can link to directories | No | Yes |
| Shown in `ls -l` as | A normal file, link count increases | `l` type, with `-> target` |

### See It for Yourself

Output (captured on a Linux machine):

```text
$ echo "Hello from the original file" > original.txt
$ ln original.txt hardlink.txt
$ ln -s original.txt softlink.txt
$ ls -li
total 8
1123508 -rw-r--r-- 2 root root 29 Oct 21 19:09 hardlink.txt
1123508 -rw-r--r-- 2 root root 29 Oct 21 19:09 original.txt
1123509 lrwxrwxrwx 1 root root 12 Oct 21 19:09 softlink.txt -> original.txt
```

- `original.txt` and `hardlink.txt` share inode **1123508**, and the link count is **2**.
- `softlink.txt` has its own inode and simply stores the path `original.txt` (12 bytes).

Now delete the original:

```text
$ rm original.txt
$ ls -l
total 4
-rw-r--r-- 1 root root 29 Oct 21 19:09 hardlink.txt
lrwxrwxrwx 1 root root 12 Oct 21 19:09 softlink.txt -> original.txt
$ cat hardlink.txt
Hello from the original file
$ cat softlink.txt
cat: softlink.txt: No such file or directory
```

The hard link still reaches the data; the soft link points at a name that no longer exists.

## cp vs mv

| | `cp` | `mv` |
|---|---|---|
| Result | A **new** file with a new inode | The **same** file under a new name or location |
| Original | Kept | Gone from the old place |
| Within one file system | Copies all the data | Only updates the directory entry: instant, even for huge files |
| Across file systems | Copies the data | Copies, then deletes the original |

Output (captured on a Linux machine):

```text
$ echo data > a.txt
$ ls -i a.txt
1123510 a.txt
$ cp a.txt b.txt
$ ls -i b.txt
1123511 b.txt
$ mv a.txt c.txt
$ ls -i c.txt
1123510 c.txt
```

The copy got a new inode (1123511); the moved file kept its inode (1123510).

### Useful Options

| Command | Effect |
|---|---|
| `cp -r dir1 dir2` | Copy a directory recursively |
| `cp -p file dest` | Preserve owner, permissions and timestamps |
| `cp -a dir1 dir2` | Archive mode: recursive and preserve everything (best for backups) |
| `cp -i`, `mv -i` | Ask before overwriting |
| `mv -v` | Show what was moved |

## Questions

1. A 50 GB file is moved to another directory on the same partition. Why is it instant?
2. You need a shortcut from `/opt/app/current` to `/opt/app/v2.3`, a directory. Which link type, and what command?
3. A file has a link count of 3. How many names point to its inode?

<details>
<summary>Answers</summary>

1. `mv` only rewrites the directory entries; the inode and data never move.
2. A soft link, since hard links can't point to directories: `ln -s /opt/app/v2.3 /opt/app/current`.
3. Three hard links (names).
</details>
