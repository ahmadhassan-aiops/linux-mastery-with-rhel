# 15. Daemons and Services

A **daemon** is a process that runs in the background, with no terminal, and keeps running until it is stopped. Daemons provide **services**: the SSH server (`sshd`), the scheduler (`crond`), the web server (`httpd`), logging (`rsyslogd`). Their names often end in **d**.

Compare:

- `df -h` starts, prints its result and exits: an ordinary process.
- `sshd` starts at boot and waits for connections until shutdown: a daemon.

| Kind | Examples | If it is killed |
|---|---|---|
| **Application daemons** | `httpd`, `mysqld`, `vsftpd` | That application stops; the system keeps running |
| **System daemons** | `systemd`, `systemd-journald`, `dbus-daemon` | The system may become unusable or crash |

## Managing Services with systemctl (RHEL 7 and Later)

```bash
systemctl status sshd          # running? enabled? recent log lines
systemctl start httpd          # start now (loads it into RAM)
systemctl stop httpd           # stop now
systemctl restart httpd        # stop and start
systemctl reload httpd         # re-read the configuration without stopping
systemctl enable httpd         # start automatically at boot
systemctl enable --now httpd   # enable and start in one step
systemctl disable httpd        # don't start at boot
systemctl is-active httpd
systemctl is-enabled httpd
systemctl list-units --type=service              # loaded services
systemctl list-unit-files --type=service         # every service and whether it is enabled
systemctl --failed                               # services that failed
journalctl -u httpd -f                           # follow a service's log
```

## The Old Way (RHEL 6)

```bash
service httpd start | stop | restart | status
chkconfig httpd on           # start at boot
chkconfig --list             # boot settings of every service
```

On RHEL 7 and later the `service` command still works: it forwards to `systemctl`.

## Questions

1. After installing `httpd` you reboot and the website is down. What did you forget?
2. You edited `/etc/ssh/sshd_config`. Which command applies it without dropping current SSH sessions?

<details>
<summary>Answers</summary>

1. `systemctl enable httpd` (or `enable --now`).
2. `systemctl reload sshd`.
</details>
