# 01. The Filesystem Hierarchy Standard

The **Filesystem Hierarchy Standard (FHS)** defines which directory holds what on a Linux system. Because every distribution follows it, you always know where to look for configuration, logs or programs.

![The Linux filesystem hierarchy](../images/filesystem-hierarchy.png)

## The Top-Level Directories

| Directory | Contains | Example |
|---|---|---|
| `/` | The root of the whole tree | |
| `/boot` | The kernel, initramfs and boot loader files | `vmlinuz-5.14.0-...`, `grub2/` |
| `/etc` | System-wide **configuration** files (text) | `/etc/fstab`, `/etc/passwd`, `/etc/ssh/sshd_config` |
| `/home` | Home directories of normal users | `/home/ahmad` |
| `/root` | Home directory of the root user | |
| `/usr` | Installed programs, libraries and documentation | `/usr/bin`, `/usr/lib`, `/usr/share/doc` |
| `/bin`, `/sbin` | User and admin commands. On RHEL 7 and later they are links to `/usr/bin` and `/usr/sbin` | `ls`, `fdisk` |
| `/lib`, `/lib64` | Shared libraries and kernel modules (links into `/usr` on RHEL 7+) | `/lib/modules/` |
| `/var` | **Variable** data that grows: logs, mail, spool, caches, websites | `/var/log`, `/var/spool/cron`, `/var/www/html` |
| `/tmp` | Temporary files for everyone, often cleaned on reboot | |
| `/opt` | Optional, add-on software from third parties | `/opt/google/chrome` |
| `/dev` | **Device files**: disks, terminals, USB | `/dev/sda`, `/dev/tty1`, `/dev/null` |
| `/proc` | A virtual file system showing the running kernel and every process (lives in RAM) | `/proc/cpuinfo`, `/proc/meminfo` |
| `/sys` | Another virtual file system describing devices and drivers | `/sys/class/scsi_host/` |
| `/run` | Runtime data since the last boot (PID files, sockets) | |
| `/mnt`, `/media` | Mount points for temporary file systems and removable media | `/media/USB` |
| `/srv` | Data served by the system (FTP, web) on some setups | |

## Two Ideas to Remember

- **Everything is a file.** Disks (`/dev/sda`), terminals (`/dev/pts/0`), even running processes (`/proc/1234`) appear as files you can read.
- **`/etc` is for configuration, `/var` is for data that changes.** When something breaks, check its config in `/etc` and its log in `/var/log`.

## Explore

```bash
ls /                       # the top level
ls -l /bin                 # on RHEL: a link to usr/bin
cat /proc/cpuinfo | head   # CPU details, straight from the kernel
ls /var/log                # system logs
man hier                   # the manual page describing the hierarchy
```

## Questions

1. You changed the SSH server settings. Which directory holds the file?
2. Where would you look for the Apache web server's error log?
3. Why does `/proc` take no space on disk?

<details>
<summary>Answers</summary>

1. `/etc/ssh/` (the file is `/etc/ssh/sshd_config`).
2. `/var/log/httpd/error_log`.
3. It is a virtual file system generated by the kernel in RAM; it disappears at shutdown.
</details>
